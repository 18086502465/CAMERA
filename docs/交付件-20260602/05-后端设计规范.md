# 后端设计规范

## 1. 技术栈

| 项 | 选型 |
|---|---|
| 语言 | Java 8 |
| 框架 | Spring Boot 2.7.15 |
| Web | spring-boot-starter-web |
| ORM | MyBatis-Plus 3.5.3.1 |
| 数据源 | Druid |
| 数据库 | MySQL 8.0 |
| 鉴权 | Spring Security + JWT |
| Excel | Apache POI |
| 日志 | SLF4J + Spring Boot Logging |
| 发布 | Spring Boot fat jar + Windows 服务包装器 |

## 2. 分层规范

```text
controller  接口入参校验、返回 ResultVO
service     业务规则、事务、聚合逻辑
mapper      数据库访问
entity      数据库实体映射
dto         接口请求/响应对象
vo          统一响应和视图对象
task        定时任务
config      安全、MyBatis、Web 配置
utils       通用工具
```

## 3. Controller 规范

- Controller 只做：参数接收、基础校验、调用 Service、返回结果。
- 不在 Controller 中写复杂 SQL 或跨表业务。
- 新接口优先使用 `/api/v1/...` 或 `/api/{resource}` 风格。
- 设备上报接口必须校验：
  - `Authorization: Bearer <token>`。
  - `X-Device-Id`。
- 上传接口必须限制文件类型、大小、数量。

## 4. Service 规范

- Service 负责业务事务。
- 写入多张表时使用 `@Transactional(rollbackFor = Exception.class)`。
- 不允许由心跳修改相机所属产线/工位，归属关系只由配置管理维护。
- 文件写入和数据库写入要保证相对一致；失败时返回可理解原因。
- 聚合统计要明确时间口径、班次口径、筛选范围。

## 5. Mapper 规范

- 简单 CRUD 使用 MyBatis-Plus。
- 复杂统计 SQL 放到 XML Mapper 或 Service 内集中维护。
- SQL 必须使用参数绑定，禁止字符串拼接用户输入。
- 分页查询必须限制 `size` 最大值，避免一次性加载过多。

## 6. 统一返回规范

接口统一返回 `ResultVO<T>`：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

建议：

- 成功：`code=200`。
- 参数错误：`code=400` 或当前 `fail` 约定。
- 鉴权失败：HTTP 401 或统一业务码。
- 服务异常：返回友好 message，详细异常写日志。

## 7. 鉴权规范

当前实现：

- 前端登录后保存 JWT。
- `JwtRequestFilter` 解析 Token。
- 部分设备接口仅检查 Bearer 前缀和设备 ID。

目标规范：

- 用户接口使用 JWT 鉴权。
- 设备接口使用设备 Token/签名机制。
- 设备 Token 应独立于用户 Token。
- Token 不应硬编码在配置或源码中。
- 生产环境必须替换 `jwt.secret`。

## 8. 文件上传规范

- 缺陷图片上传目录：`${app.home}/data/uploads/defect-images/`。
- 兼容图片目录：`${app.home}/data/uploads/images`。
- 支持格式：jpg/jpeg/png/bmp/gif/webp/svg，其中 jpg/png/bmp/gif 需要能被解析。
- 单批图片数量建议不超过 50。
- 文件路径必须做 normalize 和 root 校验，防止路径穿越。
- 数据库存储相对访问 URL，不将本地路径暴露给前端。

## 9. 日志规范

- 应用日志：`${app.home}/logs/camera-detection-system.log`。
- Windows 服务包装器日志：`logs/service-wrapper.log`、`service-out.log`、`service-err.log`。
- 用户操作写入 `sys_operation_log`。
- 异常日志记录堆栈，接口返回简明错误。
- 生产环境不建议开启 MyBatis SQL DEBUG。

## 10. 异常处理规范

- 参数异常：抛出 `IllegalArgumentException` 或返回明确失败。
- 文件异常：返回错误码、失败原因、处理建议。
- 数据库异常：日志记录 SQL/表名上下文，返回“服务暂不可用”。
- 接口不能直接返回 Java 原始异常堆栈给前端或设备。

## 11. 数据清理规范

默认策略应可配置：

| 数据 | 保留 | 动作 |
|---|---:|---|
| 缺陷图片文件 | 30 天 | 删除文件和图片记录。 |
| 缺陷框 metadata | 90 天 | 归档或保留摘要。 |
| 检测历史明细 | 90 天 | 归档到历史表。 |
| 30 分钟事实 | 1 年 | 保留。 |
| 操作日志 | 180 天 | 清理。 |

## 12. 后端质量门禁

- Maven 编译通过：`mvn -q -DskipTests clean package`。
- 核心接口必须有 Postman/自动化验收样例。
- 相机上报接口必须覆盖：成功、缺 Token、缺设备、缺字段、文件名不匹配、图片损坏。
- 配置删除必须覆盖依赖校验。
- 发布前必须验证 jar 内包含 `static/index.html` 和 `assets`。
