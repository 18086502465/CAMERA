## 2. 总体结论

当前项目已经具备从“页面原型”向“可安装运行系统”交付的基础能力：

- Vue 前端可构建并集成到 Spring Boot。
- 8091 统一提供页面和 API。
- 缺陷图片多图上传、最近图片展示、相机状态、配置管理等关键能力已落地。
- 已生成 Windows 安装 exe，并内置 JRE。
- 已具备杭州工厂专项自动化验收脚本和报告。

但仍存在若干需要在 P0/P1 继续优化的问题，尤其是鉴权、相机配置/状态拆分、接口路径一致性、数据库迁移机制和代码编码可读性。

## 4. 主要风险与问题

### P0 问题

| 编号 | 问题 | 影响 | 建议 |
|---|---|---|---|
| P0-001 | 设备 Token 校验较弱 | 当前部分设备接口只检查 Bearer 前缀，存在伪造上报风险。 | 增加设备 Token 表，按 `X-Device-Id` 校验 token 或签名。 |
| P0-002 | `camera_status` 同时承载配置和实时状态 | 高频心跳写入可能影响配置管理，模型边界不清晰。 | 拆分为 `dim_camera` 和 `camera_status_snapshot`。 |
| P0-003 | 前端部分 API 封装与后端路径不完全一致 | 后续打开未使用页面时可能出现 404，如部分 `brands/companies/holidays/anomaly` 封装需复核。 | 统一梳理前端 API 文件和 Controller 路径，删除旧封装或补兼容接口。 |
| P0-004 | 生产配置中 MyBatis SQL DEBUG 偏重 | 日志量大，影响磁盘和性能。 | 发布模板已设为 INFO，本地开发配置也建议按环境区分。 |
| P0-005 | 数据库无版本迁移机制 | 现场升级容易漏字段或重复执行 DDL。 | 引入 Flyway/Liquibase 或维护 `db/migration` 版本脚本。 |

### P1 问题

|---|---|---|---|

## 5. 模块评审

### 5.1 前端

优点：

- 页面结构清晰，路由完整。
- Layout 统一顶部筛选和 Tab。
- 图像记录组件可复用。
- 分页长度 5/10/20/50 已形成规范。

建议：

- 统一 API 封装路径，避免旧页面调用不存在接口。
- 抽取通用分页表格组件。
- 空状态、异常状态、加载状态继续标准化。
- 对图片加载失败做统一组件，不在多个页面重复写逻辑。

### 5.2 后端

优点：

- Controller/Service/Mapper 基本分层。
- `DefectImageServiceImpl` 对多图上传、文件名匹配、图片解析、失败原因做了较多处理。
- 配置删除依赖校验已开始落地。
- 发布场景外部配置已完成。

建议：

- 强化鉴权，尤其设备上报接口。
- 拆分过大的 Controller/Service。
- 增加全局异常处理器。
- 返回码和 HTTP 状态码统一。
- 增加接口层 DTO 校验注解，如 `@NotBlank`、`@Max`。

### 5.3 数据库

优点：

- 维表、事实表、图片表、系统表基本齐全。
- 缺陷图片 batch/file/box 结构合理。
- 30 分钟事实表支撑良率趋势。

建议：

- 强化唯一键和外键/软外键约束。
- 为高频查询补充索引。
- 引入迁移版本。
- 相机状态与相机配置拆分。

### 5.4 发布部署

优点：

- 已生成安装 exe。
- 内置 JRE，降低目标机依赖。
- Windows 服务脚本完整。
- 外部配置、日志、上传目录已解耦。

建议：

- Inno 安装界面当前使用默认语言资源，后续可补中文语言包。
- 增加安装前端口占用检查。
- 增加 MySQL 连通性检查。
- 增加卸载时保留数据目录的提示。
