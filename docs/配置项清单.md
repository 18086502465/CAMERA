# 配置项清单

> **用途**：现场改配置有据可依，不必翻源码。
> **基准日期**：2026-11-04
> **适用范围**：Linux 版（`installer/linux/`）。Windows 版已停止维护。

---

## 一、配置分层与加载顺序

```
优先级从低到高：
  ① JAR 内置  fact-product/src/main/resources/application.yml   （开发默认值，无凭据）
  ② 外部配置  /opt/camera-detection-system/config/application.yml （现场实际生效，权限 640）
  ③ 环境变量  /etc/default/camera-detection                       （640 root:root，只放密钥）
```

**关键规则（2026-11-04 安全改造后）**：

- 外部配置与模板中**不再出现任何明文口令**，一律用 `${MYSQL_PASSWORD}` / `${JWT_SECRET}` 占位。
- 占位符**没有默认值**（写成 `${MYSQL_PASSWORD}` 而非 `${MYSQL_PASSWORD:}`）：
  环境变量缺失时应用**启动即失败**，并在日志明确报 `Could not resolve placeholder`。
  这比"能启动但连不上库"好得多 —— 后者表现为"服务 active 但业务全错"，极难排查。
- 外部配置按 **key 合并**（不是整文件替换）：外部配置里**省略的 key 仍取 JAR 内置值**。
  因此生产环境必须显式覆盖以下两项，否则会用开发期的 DEBUG 日志与 StdOut 日志实现：

  ```yaml
  mybatis-plus:
    configuration:
      log-impl: org.apache.ibatis.logging.slf4j.Slf4jImpl   # 必须是 Slf4jImpl
  logging:
    level:
      com.wms.mapper: INFO                                  # 必须是 INFO
  ```

## 二、环境变量（`/etc/default/camera-detection`，640 root:root）

| 键 | 是否敏感 | 默认值 | 作用 | 备注 |
|---|---|---|---|---|
| `JAVA_OPTS` | 否 | `-Xms512m -Xmx1024m` | JVM 堆参数 | **必须带引号**。run.sh 用 `source` 读取本文件，不加引号时空格会截断 → `-Xmx1024m: command not found` → 启动失败 |
| `INSTALL_DIR` | 否 | `/opt/camera-detection-system` | 程序安装目录 | 改路径需同步 systemd `ReadWritePaths` |
| `WORK_DIR` | 否 | `/var/lib/camera-detection-system` | 运行数据目录（日志、上传落盘） | |
| `APP_HOME` | 否 | 同 `WORK_DIR` | 应用主目录，决定日志与图片落盘位置 | |
| `JAVA_HOME` | 否 | `/usr/lib/jvm/java-8-openjdk-amd64` | Java 运行时 | 留空则依次尝试 内置 jre → JAVA_HOME → PATH |
| `CONFIG_FILE` | 否 | `${INSTALL_DIR}/config/application.yml` | 外部配置文件路径 | |
| `MYSQL_PASSWORD` | **是** | 无 | MySQL root 口令 | **必填**。缺失则服务启动失败 |
| `JWT_SECRET` | **是** | 无（install.sh 生成 64 位随机十六进制） | JWT 签名密钥 | **必填**。轮换会使已签发令牌失效 |
| `ADMIN_USER` | 否 | `admin` | 管理员账号名 | |
| `ADMIN_PASSWORD` | **是** | 无 | 管理员口令（BCrypt 存库） | 改密用 `reset-password.sh` |
| `BACKUP_DIR` | 否 | `/data/camera-detection/backup/db` | 数据库备份目录 | |
| `KEEP_FULL_DAYS` | 否 | `14` | 全量备份保留天数 | |
| `MAX_DISK_USE` | 否 | `85` | 备份前磁盘使用率上限（%），超过则跳过备份 | |

## 三、应用配置（`application.yml`）

### 3.1 服务与数据源

| 键 | 默认值 | 作用 | 现场是否需改 |
|---|---|---|---|
| `server.port` | `8091` | HTTP 端口 | 否（改 nginx 反代需同步） |
| `spring.datasource.url` | `jdbc:mysql://localhost:3306/wms-new?...` | 数据库连接串 | 库名/地址变化时改 |
| `spring.datasource.username` | `root` | 数据库账号 | 按需 |
| `spring.datasource.password` | `${MYSQL_PASSWORD}` | 数据库口令 | **不要在此写明文** |
| `spring.datasource.druid.max-active` | `200` | 连接池上限 | 高并发时调大 |
| `spring.datasource.druid.max-wait` | `60000` | 获取连接超时（ms） | |
| `spring.servlet.multipart.max-file-size` | `10MB` | 单文件上限 | 大图场景调大 |
| `spring.servlet.multipart.max-request-size` | `1024MB` | 单请求上限 | **nginx 还需 `client_max_body_size 1024m`**，否则图片上传 413 |

### 3.2 认证与日志

| 键 | 默认值 | 作用 | 现场是否需改 |
|---|---|---|---|
| `jwt.secret` | `${JWT_SECRET}` | JWT 签名密钥 | **不要在此写明文** |
| `jwt.expiration` | `86400000`（24 小时） | 令牌有效期（ms） | 按需 |
| `mybatis-plus.configuration.log-impl` | `StdOutImpl` | MyBatis 日志实现 | **生产必须改为 `Slf4jImpl`** |
| `logging.level.com.wms.mapper` | `DEBUG` | Mapper 日志级别 | **生产必须改为 `INFO`** |
| `logging.file.name` | `${app.home}/logs/camera-detection-system.log` | 日志文件 | |

### 3.3 业务相关

| 键 | 默认值 | 作用 | 现场是否需改 |
|---|---|---|---|
| `app.home` | `${APP_HOME:./runtime}` | 应用主目录 | 启动时由 `-Dapp.home` 覆盖 |
| `defect-image.max-batch-images` | `100` | 单批缺陷图上限 | 设备端批量超此值会返回 413 |
| `defect-image.upload.dir` | `${app.home}/data/uploads/defect-images/` | **缺陷图片实际落盘目录** | **改路径必须同步 systemd `ReadWritePaths`**，否则上传成功但不落盘 |
| `server-metrics.interval-ms` | `5000` | 服务器指标采集间隔（ms） | |
| `server-metrics.history-size` | `120` | 指标历史点数（120×5s = 10 分钟窗口） | |

## 四、systemd 单元

| 项 | 值 | 说明 |
|---|---|---|
| 服务名 | `camera-detection` | |
| 配置文件 | `/etc/default/camera-detection` | 通过 `EnvironmentFile` 注入环境变量 |
| 外部配置 | `/opt/.../config/application.yml` | 通过 `--spring.config.additional-location` 加载 |
| 可写目录 | `ReadWritePaths` | 改图片目录/日志目录时**必须同步**，否则报"上传成功但不落盘" |
| 重启策略 | `Restart=always`，`StartLimitIntervalSec`/`StartLimitBurst` 写在 `[Unit]` 段 | 写在 `[Service]` 段不生效 |

## 五、数据保留策略

| 数据 | 保留期 | 清理方式 |
|---|---|---|
| `defect_image_file` / `defect_image_box` | **7 天** | `cleanup-defect-images.sh`（cron 03:30，按 mtime） |
| `defect_image_batch` | 30 天 | 同上 |
| `camera_images`（兼容表） | 30 天 | 应用内 `DataCleanupTask`（每天 02:00） |
| `fact_production_30min` | 归档 3 个月 | 同上 |
| `sys_operation_log` | 6 个月 | 同上 |
| 数据库全量备份 | 14 份 + sha256 | systemd timer（每日 01:00，zstd 压缩） |

> ⚠️ `sys_data_retention_policy` 表里存了 5 条策略，但**代码从不读它** —— 上表的真实机制是
> `DataCleanupTask` 里**硬编码**的三条 + `cleanup-defect-images.sh` 兜底。
> 不要以为改了那张表就能改保留期。

## 六、快速排查入口

| 想知道 | 执行 |
|---|---|
| 服务是否健康 | `sudo /opt/camera-detection-system/scripts/service.sh health` |
| 配置与密钥是否正常 | `sudo /opt/camera-detection-system/scripts/service.sh config-check` |
| 线上跑的是哪个版本 | `sudo /opt/camera-detection-system/scripts/service.sh version` |
| 回滚到上一版本 | `sudo /opt/camera-detection-system/scripts/service.sh rollback` |
| 清理过量 JAR 备份 | `sudo /opt/camera-detection-system/scripts/service.sh cleanup 5` |
| 完整自检（28 项） | `sudo -S env VERIFY_PASSWORD='<管理员口令>' MYSQL_PASSWORD='<数据库口令>' bash /opt/camera-detection-system/scripts/verify.sh` |

> `verify.sh` **必须以 root + 正确口令运行**，否则会有 7 项误报失败
> （640 root 的 `/etc/default` 普通用户读不到，DB 连通性检查无法执行）。
