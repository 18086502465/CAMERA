## 二、问题 1：超时查询 —— 根因与优化

### 2.1 根因定位

服务器 MySQL 慢查询日志（`/var/log/mysql/slow.log`）里，每分钟稳定出现一条 3 秒的慢 SQL：

```
# Query_time: 3.517807  Rows_sent: 10  Rows_examined: 3020590
SELECT COALESCE(NULLIF(f.camera_id,''), f.camera_name) camera_key, ...
FROM defect_image_file f
LEFT JOIN camera_status cs ON cs.id = (
  SELECT cs2.id FROM camera_status cs2
  WHERE (cs2.camera_code = f.camera_id OR cs2.camera_name = f.camera_name)
  ORDER BY CASE WHEN cs2.camera_code = f.camera_id THEN 0 ELSE 1 END, cs2.id DESC LIMIT 1)
...
GROUP BY COALESCE(NULLIF(f.camera_id,''), f.camera_name);
```

`EXPLAIN` 实锤：

```
1  PRIMARY  f          ALL             71781  100.00  Using temporary; Using filesort
1  PRIMARY  cs         eq_ref  PRIMARY  8      func,const 1
2  DEPENDENT SUBQUERY  cs2  ALL  uk_camera_code  18  19.00  Using where; Using temporary; Using filesort
```

MySQL 8 把这个写法优化成 **DEPENDENT SUBQUERY** —— 对 `defect_image_file` 的**每一行**都重新执行一次 `camera_status` 的全表扫描 + 临时表 + filesort。扫描行数 **302 万**（表本身才 7.4 万行）。

该 SQL 来自 `/api/v1/defect-images/camera-summaries`，被 `CameraStatusView`（30 秒轮询）与 `CameraImageRecords` 调用。

### 2.2 三个叠加问题

| 问题 | 说明 | 严重度 |
|---|---|---|
| **① 相关子查询** | 见上，302 万行扫描 | 主因 |
| **② N+1 查询** | `listCameraSummaries` 在 RowMapper 里对**每一行**汇总调用 `listRecent()`；`listRecent` 又对**每张图**调用 `listDefects(imageId)` | 10 相机 × N 张图 = 几十次额外查询 |
| **③ 每次请求跑 DDL** | `ensureSchema()` 每次被调用都执行 3 条 `CREATE TABLE IF NOT EXISTS` + 5 条 `ensureColumn` + 6 条 `ensureIndex` | DDL 拿 InnoDB **元数据锁（MDL）**，与慢查询叠加会把整表查询排队 |

### 2.3 修复内容

**① JOIN 改为走唯一索引直连**

```java
// 修复前（相关子查询）
"LEFT JOIN camera_status cs ON cs.id = (SELECT cs2.id FROM camera_status cs2 WHERE ...)"

// 修复后
"LEFT JOIN camera_status cs ON cs.camera_code = f.camera_id "
```

**依据**（服务器实测）：
- `defect_image_file.camera_id` 存的是**设备编号**，与 `camera_status.camera_code` 一一对应：**10/10 组匹配，0 组落空**
- `camera_status.camera_code` 上有唯一索引 `uk_camera_code` → JOIN 走 `eq_ref`，单次索引查找
- 原 `OR cs2.camera_name = f.camera_name` 分支实测 **0 条命中**（图片里的 `camera_name` 是中文工位名「内装外形检测」，与 `camera_status.camera_name` 的「CV5-Cam1」式命名完全不相交），属历史兼容残留，可安全移除

**② 汇总查询改两段式聚合**

```
第 1 段：只扫 defect_image_file 做 GROUP BY → 结果只有 10 行（按相机）
第 2 段：拿这 10 行去 JOIN camera_status / dim_workstation / dim_production_line
```

JOIN 的行数从 7.4 万降到 10。同时把维度过滤（工厂/产线/工位）与行级过滤（相机编号/严重度/时间）分层 —— 维度过滤放外层（那里才有 `cs/ws/pl` 别名），行级过滤放内层。

**③ 消除 N+1**

- `listRecentForSummaries()`：用**窗口函数** `ROW_NUMBER() OVER (PARTITION BY camera_id ORDER BY ...)` 一次查出每个相机最近 N 张，并**先分组再 JOIN**（只对 50 行 JOIN，而不是 8 万行）
- `listDefectsByImageIds()`：批量查多张图的缺陷框，替代逐图 `listDefects(imageId)`

**④ ensureSchema 限频**

启动时（`@PostConstruct`）完整执行一次；运行期改为**只读的存在性检查 + 5 分钟时间戳缓存**。表被人为删除时最多 5 分钟自愈，期间不产生 DDL 风暴。

### 2.4 优化效果（服务器实测）

| 接口 | 修复前 | 修复后 | 提升 |
|---|---|---|---|
| `/api/v1/defect-images/camera-summaries?latestLimit=5` | 6.363 s | **0.920 s** | **6.9×** |
| `/api/v1/defect-images/camera-summaries?latestLimit=1&lineId=3` | 4.082 s | **0.851 s** | **4.8×** |

慢查询日志中**不再有 >1 秒的慢 SQL**；原「每分钟 3 秒」的慢查询已消失。

配置页浏览器实测加载：**5541 ms → 2034 ms**，且**无任何超过 1 秒的请求**。

### 2.5 语义等价性验证

- 两段式聚合 vs 单段 JOIN → **完全一致**

## 三、问题 2：层级树只展开到工位层级

### 3.1 根因

层级树在工位节点下继续挂相机节点，但点击相机节点时：

```javascript
// 修复前：三个独立 if，camera 类型节点一个条件都不匹配 → 不传任何过滤参数
if (activeMenu.value === 'camera') {
  if (node.type === 'factory') params.factoryId = node.id
  if (node.type === 'line') params.lineId = node.id
  if (node.type === 'workstation') params.stationId = node.id
}
```

后端 `/api/cameras` 没收到任何筛选条件 → 返回**全部 16 台相机**。浏览器实测确认：点击 `CV1_Cam1` 后右侧显示「共 16 条」，只有排序变化，筛选没生效。

### 3.2 修复

按用户要求「展开层级只能到工位层级」：

1. **删除工位下的相机子节点** —— 层级变为 工厂 → 产线 → 工位
2. **`appendContextParams` 改为 `else if` 链** —— 每一层都有确定的过滤参数
3. **`handleTreeSelect` 移除 camera 分支**（保留注释说明兼容处理）

### 3.3 验证

```

→ 相机节点数 = 0 ✅
```

## 四、问题 3：配置层级窗口可拖动 + 完整工位名

### 4.1 修复内容

**可拖动调宽**（`frontend/src/views/system/ConfigView.vue`）

- 侧边栏右边缘新增 `.sidebar-resizer` 拖拽把手
- 宽度写入 CSS 变量 `--sidebar-width`，由 `.config-sidebar` 消费
- `mousedown` / `touchstart` 开始拖动，`mousemove` / `touchmove` 实时改宽
- 宽度持久化到 `localStorage`（`camera-config-sidebar-width`），刷新后保持
- 双击把手恢复默认 288px；方向键 `←/→` ±20px 微调（无障碍，`role="separator"` + `aria-valuenow`）
- 拖动中给 `.config-layout` 加 `.resizing` class 禁用宽度过渡，保证跟手
- 组件卸载时 `onBeforeUnmount` 清理全局监听，避免内存泄漏
- 移动端（≤900px）隐藏把手

**完整工位名**

- `.tree-label` 从 `text-overflow: ellipsis; white-space: nowrap` 改为 **允许换行完整展示**（`white-space: normal; word-break: break-word`）
- 额外加 `:title="data.label"` —— 即使极端窄宽度下被截断，鼠标悬停也能看到完整名称
