# 产线缺陷在线 AI 检测系统 —— 后端模块设计

> 版本：1.0（2026-11-05，DDD 重构 P0~P5 完成后定稿）
> 上游文档：《架构说明》（分层规则、依赖铁律、协作模式）｜本文档描述**各业务域**的职责边界、内部结构与关键设计决策

---

## 阅读约定

- 每域结构 = `api`（HTTP 层）/ `app`（应用服务 + 事件 + 端口）/ `domain/model`（实体）/ `infra`（mapper + repository + task）
- 「下游依赖」只列**跨域**协作（域内 api→app→infra 调用不赘述）
- 端点数、类名均来自当前代码实测（2026-11-07：163 文件 / 28 Controller / 135 端点）；各域行数为 `wc -l` 实测

## 1. iam —— 身份与访问管理（19 文件 / 2,672 行）

**职责**：登录认证（JWT）、用户管理、操作日志审计、安全配置。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `AuthController`、`SysUserController`、`SysOperationLogController` + `dto/OperationLogQueryDTO` | 登录/注册、用户 CRUD |
| app | `ISysUserService/Impl`、`ISysOperationLogService/Impl` | 用户查询带工厂/产线关联名 |
| domain | `JwtUtil`、`model/SysUser`、`model/SysOperationLog` | JWT 签发/校验读环境变量（无明文兜底） |
| infra | `JwtRequestFilter`（只解析 token，401/403 分派交 `ExceptionTranslationFilter`）、`SecurityConfig`（白名单精确到方法+路径）、`OperationLogAspect`（切点 `com.wms.*.api..*`，七域 api 全覆盖）、`repository/OperationLogRepository`（查询 SQL 收敛先例） | |

**注意**：`SysUserService.findByUsername` 失败返回 null → login 返回 `ResultVO.fail(500)`；禁用用户同理。口令哈希算法与重置脚本（`reset-password.sh`）绑定，勿改。

## 2. masterdata —— 主数据档案（37 文件 / 1,773 行）

**职责**：工厂 / 产线 / 工位 / 品牌 / 班次 / 节假日 / 公司七类主数据的 CRUD 与**删除保护**、级联树下发。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `CascadeController`（`/api/cascade/all` 单条 GROUP BY 无 N+1，每工位带 `cameraCount`）、`DimFactory/ProductionLine/Workstation/ProductBrand/Company/ShiftController`、`SysHolidayConfigController` | 删除前依赖检查（工位/相机/产量/检测记录任一存在 → `ResultVO.fail` 带明细） |
| app | 7 组 `I*Service/Impl` | 修改产线/工位时**联动同步**：`camera_status.line_id`、`dim_camera` 的 factory/line/workstation、`cfg_camera_defect_mapping` 位置字段 |
| domain | `model/Dim*` ×6 + `SysHolidayConfig` | ID 类型 **Integer**（写错编译能过但行为变，历史踩坑） |
| infra | 7 个 Mapper + `MasterDataRepository`（P3 批次①：19 处 SQL 收敛，含 2026-11-04 现场修正的依赖检查语义注释） | |

**下游依赖**：无（被 device/analytics/defect 依赖）。

## 3. device —— 相机设备域（20 文件 / 2,788 行）

**职责**：相机心跳接收、状态快照维护、设备侧异常告警发布、服务器指标、相机档案级联管理。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `CameraStatusHeartbeatController`（心跳入口，幂等响应 `needUpload`）、`CameraImageController`、`ServerMetricsController` + `dto/*`、`vo/ServerMetricsVO` | |
| app | `CameraStatusServiceImpl`（416 行核心：心跳处理 + 5 类告警判定 + 阈值读取）、`CameraDirectory`/`CameraDirectoryAdapter`（**跨域端口**，14 方法）、`SystemSettingReader`（**跨域端口**，读告警阈值）、`event/CameraAlertEvent`（**进程内事件**） | 告警经事件发布给 analytics，本域不感知落库结果 |
| domain | `model/CameraStatus`（id 是 **Long**）、`model/CameraImage` | |
| infra | 2 个 Mapper + `CameraDirectoryRepository`（相机档案级联查询/删除/upsert） | |

**下游依赖**：`system`（经 `SystemSettingReader` 端口，不直接依赖其 Repository）。
**被依赖**：analytics/defect/system 经 `CameraDirectory` 端口；analytics 经 `CameraAlertEvent` 事件。

## 4. defect —— 缺陷图片域（9 文件 / 3,134 行）

**职责**：现场**主通道** —— 缺陷图片接收、落盘、检索、历史查询。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `DefectImageController`（upload / page / history / camera-summaries / recent 等）+ `dto/DefectImageUploadMetadataDTO`、`dto/DefectImageUploadResultDTO` | 上传限流配置在 shared |
| app | `IDefectImageService` / `DefectImageServiceImpl`（1,071 行：上传解析 metadata、`ensureSchema` 限频自愈守卫、图片路径规则 `{yyyyMMdd}/{cameraId}/{HHmmssSSS}_{uuid8}.{ext}`） | `camera_id` 存的是 **camera_code** |
| infra | `DefectImageRepository`（954 行：3 表建表 + 补列 + 补索引 `ensureSchemaFull`、检索 SQL、磁盘文件删除） | P5：ensureSchemaFull 由 SchemaInitializer 启动期调度 |

**下游依赖**：`device.infra.mapper.CameraImageMapper/CameraStatusMapper`（**冻结存量**，P6 清零任务：经 `CameraDirectory` 端口替换）。
**业务口径**：`defect_image_file/_box` 主表 31 天 → 按月归档表 730 天；磁盘图片文件 730 天（按日期目录删，Java 侧不删文件）；图片目录 `/data/camera-detection/images/defect-images/`；改路径必须同步 systemd `ReadWritePaths`。

## 5. inspection —— 批量上报冻结契约（20 文件 / 1,757 行）

**职责**：`batch-upload` 冻结契约通道（`fact_inspection_*` + `agg_*` 体系）。**基本现场不用**，改动需极谨慎。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `BatchUploadController`、`FactProductionInfoController`、`ProductDetectionHistoryController` + 5 个 dto | 契约字段勿动 |
| app | `InspectionUploadService/Impl`（事务内批量入库）、`IFactProductionInfoService`、`IProductDetectionHistoryService` | |
| domain | `model/FactProductionInfo`、`model/ProductDetectionHistory` | 注意 `ProductDetectionHistory` **实测 0 行**（真实数据走 defect 通道） |
| infra | 2 个 Mapper + `InspectionUploadRepository` | |

**约束**：此域是冻结契约 —— 只读 `agg_*` 的统计接口现场永远为 0，统计类接口必须做 `defect_image_*` 兜底（在 analytics 域实现，响应带 `dataSource`）。

## 6. analytics —— 统计分析域（29 文件 / 4,955 行，最重）

**职责**：产线统计报表（LineAnalytics）、看板（Stats/Dashboard）、相机看板、聚合任务、告警查询。

| 层 | 主要类 | 说明 |
|---|---|---|
| api | `LineAnalyticsController`（1,263 行 / 23 端点，核心报表）、`StatsController`、`CameraDashboardController`、`FactProduction30minController`、`DimTimeBucket30minController`、`FactAnomalyAlertController` | |
| app | 5 组 Service/Impl、`listener/CameraAlertEventListener`（**事件监听**：落库告警，吞 DataAccessException） | 告警 SQL 修复历史见下 |
| domain | `model/FactProduction30min/Archive`、`FactAnomalyAlert`、`DimTimeBucket30min` | |
| infra | 4 个 Mapper + **6 个 Repository**：`LineAnalyticsRepository`/`LineAnalyticsQueryRepository`（批次④拆分，Controller 从 1,511 → 1,263 行）、`StatsQueryRepository`、`AnalyticsDashboardRepository`、`AnalyticsAggregationRepository`（3 组聚合表 DDL + 定时配置）、`AnomalyAlertRepository` | |

**★ 已修复的历史 bug（勿回退）**：`fact_anomaly_alert` 的 INSERT 曾缺 `detect_time`/`message` 两个 NOT NULL 列 → SQL 报错被 catch 掩盖 → **告警上线以来从未落库**（表 0 行）。2026-11-05 P4 事件化验证时发现并修复（补列 + 补第 7 参数），实机验证落库成功。

**职责**：系统设置、数据保留清理、配置导入导出（Excel）、相机-缺陷映射维护。

| 层 | 主要类 | 说明 |

## 附：模块设计决策记录（重构过程沉淀）

| 决策 | 依据 |
|---|---|
| 端口定义放**消费方**（`device.app.CameraDirectory`） | 接口形状由消费者需要决定，提供方只做适配 |
| 事件用 Spring ApplicationEvent（进程内同步） | C2 决策：单体规模不值得引 MQ；同步保证时序与原代码一致 |
| Repository 按**表所属域**下沉，不按调用方分置 | 批次③确立：device 的 Service 查 `sys_system_setting` → SQL 放 system 域 Repository |
| 异常语义原样保留 | `countOrZero` 吞异常返回 0、`ensureColumn` 只记 WARN、`insertAnomalyAlert` 只 catch DataAccessException —— 有意设计，勿"顺手优化" |
| 写操作超 5 参数用 DTO | `CameraDefectMappingRow` 19 列防位置错位 |
| ArchUnit freeze 模式守存量 | 规则上线即红不如如实固化：13 处跨域存量只许清零不许新增 |
