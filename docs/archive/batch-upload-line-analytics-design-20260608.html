批量检测上报与产线统计图表重构方案

围绕新版 /api/v1/camera/inspection/batch-upload 协议、p0/p1 缺陷映射配置、高效数据库保存与筛选策略、可配置产线统计图表工作台进行整体设计。目标是让相机协议稳定、现场配置灵活、统计查询高效、页面图表可自助搭建。

协议版本：2.0 缺陷映射：相机 sourceCode 1 对 1 查询策略：明细追溯 + 聚合查询 图表：可新增 / 可编辑 / 可拖拽缩放

一、重构范围

本轮从接口、配置、数据库、图表四层同步重构，避免只在旧字段上继续追加功能。

API
新版上报协议废弃 dataList 与写死缺陷字段，改为批次级 summary + 动态 defects[]。
MAP
p0/p1 映射相机统一上报 sourceCode，后台按现场配置匹配标准缺陷类型，强制 1 对 1。
DB
高效存储查询原始批次、缺陷计数、映射快照、30 分钟聚合分层保存。
BI
图表工作台支持按筛选条件创建图表，调整大小布局，构建动态统计报表。

二、新版相机批量检测数据接口

相机协议固定，不再包含业务写死缺陷字段；现场变化通过后台映射配置解决。

POST /api/v1/camera/inspection/batch-upload
模块设计要点
鉴权必填 Bearer Token + X-Device-Id，设备独立 Token。
幂等cameraCode + batchId 唯一，重复上报返回幂等成功。
计数P0 推荐 INCREMENTAL 增量计数；累计模式后续兼容。
缺陷defects[].sourceCode 如 p0/p1，由后台映射为标准缺陷类型。
校验总数 = OK + NG；NG 与 defects 数量一致；映射必须唯一。
失败处理未配置/多匹配返回 422，并给出配置建议，不静默归类。
推荐首期只启用增量模式，避免累计值因相机重启、计数器清零导致重复或漏计。

四、数据库保存与筛选策略

采用“明细追溯 + 聚合查询 + 维度配置”的分层模型，确保图表查询效率。

明细层

inspection_batch

保存上报批次、相机、时间范围、产品、总数、OK、NG、原始 JSON。

缺陷层

inspection_defect_count

按 sourceCode 映射后的标准缺陷类型保存计数、位置、严重度、映射快照。

聚合层

agg_*_30m

按时间桶、产线、工位、相机、产品、班次、缺陷类型预聚合。
