# 新服务器部署操作方案 — 20 台相机现场（2026-11-10）

> 适用：新申请服务器（8 核 / 8 GB / 系统盘 100G SSD / 数据盘 1TB HDD / Ubuntu 22.04 LTS）。
> 依据：`installer/linux/` 现行脚本逐节核对（install.sh 636 行 / build-release.sh / run.sh / verify.sh 32 项）。

## 二、前置条件（机器到位后、跑安装脚本前）

```bash
# 1) 基础软件（install.sh 不装依赖）
sudo apt update
sudo apt install -y mysql-server-8.0 openjdk-8-jdk nginx chrony

# 2) 数据盘挂载 /data（install.sh 第 5a 节按 /data 是否存在决定图片路径）
sudo mkfs.xfs /dev/<数据盘>
sudo mkdir -p /data && echo '/dev/<数据盘> /data xfs defaults,noatime 0 2' | sudo tee -a /etc/fstab
sudo mount -a

# 3) 时间同步（老现场踩过：本机与服务器时钟差 4 分钟导致误判任务未执行）
sudo timedatectl set-timezone Asia/Shanghai && sudo systemctl enable --now chrony

# 4) 数据库初始安全设置（root 口令 + 仅本机监听）
sudo mysql -e "ALTER USER 'root'@'localhost' IDENTIFIED BY '<root口令>';"
# bind-address 保持 127.0.0.1（应用同机部署，无需对外开 3306）
```

> 内核参数无需调优：20 台相机写入均值 <1MB/s，默认值全部够用。

## 三、部署步骤（按序执行）

> **2026-11-10 起，下列步骤已固化为 `scripts/deploy.sh`**（随发布包分发）。它会自动完成
> 装依赖 → 挂数据盘 → 时区 → MySQL 改认证+调参 → 装应用 → 建库 → JVM 调优重启 → 验收，
> 各阶段幂等、支持 `--from pN` 续跑：
>
> ```bash
> cd /root/camera-detection-system
> sudo bash scripts/deploy.sh --disk /dev/sdb
> ```
>
> 下面的分步说明保留用于排障与人工核对。

### 步骤 1：打包传输（运维机上）

```bash
cd fact-product && mvn -B test && cd ..        # 必须全绿再打包
bash installer/linux/build-release.sh          # → dist-release/linux/camera-detection-system-1.0.0.tar.gz
# 传输 tar.gz 到新机（约 53MB）
```

### 步骤 2：建库（新机，root）

> ⚠️ 2026-11-10 更正：此前写「四段」是漏项。**05_camera_type_migration.sql 必须执行** ——
> 它给 `dim_camera` / `camera_status` 加 `camera_type` 列，清理脚本靠这一列算「哪些相机不能删」。
> 漏跑不会报错，只会让保护集恒为空 → 每小时清理中止并告警。
> `init-database.sh` 已改为按 01→05 顺序导入并做列存在性校验，直接用它即可：

```bash
cd <解压目录>/camera-detection-system
export MYSQL_PASSWORD='<root口令>'
bash scripts/init-database.sh          # 内部建库 + 逐段导入 + 校验，幂等
```

手工等价步骤（仅供核对，不建议手敲）：

```bash
cd sql
mysql -uroot -e "CREATE DATABASE IF NOT EXISTS \`wms-new\` DEFAULT CHARSET utf8mb4 COLLATE utf8mb4_general_ci;"
mysql -uroot wms-new < 01_init_schema_nodb.sql       # 01 已含 capture_time 索引（2026-11-07 合入）
mysql -uroot wms-new < 02_final_schema_p0.sql        # ★ 会 DROP 重建 21 表，仅全新库可跑
mysql -uroot wms-new < 03_system_settings.sql
mysql -uroot wms-new < 04_align_entity_columns.sql
mysql -uroot wms-new < 05_camera_type_migration.sql  # ★ 不可省：相机类型隔离（幂等）
# 06_index_tuning.sql 幂等，可不跑（索引已含于 01）
```

> 绝不使用 `dist-release` 里打包的 `wms-new.sql`（缺 15 张 P0 表）。

### 步骤 3：安装应用

```bash
cd <解压目录>/camera-detection-system
sudo env MYSQL_PASSWORD='<应用库口令>' bash scripts/install.sh
```

- 脚本自动：创建 `cdsys` 账号 → 装 `/opt/camera-detection-system` → 生成 `/etc/default/camera-detection`（640 root:root，唯一密钥源，含 256bit JWT_SECRET）→ 装 systemd + 4 个 cron/timer + 防火墙放行 8091 + logrotate → 启动服务。
- MySQL 未就绪时以 `DB_PENDING` 退出，环境就绪后**重跑同一命令**即可。
- 应用启动时 `SchemaInitializer` 会自检建表，但**初始数据（账号/字典/令牌）以四段 SQL 为准** —— 建库先行不可省。

### 步骤 4：内存调优（8GB 机器必做）

```bash
# 1) JVM 堆（run.sh 默认 -Xmx1024m，通过 /etc/default 覆盖）
echo 'JAVA_OPTS=-Xms512m -Xmx2048m' | sudo tee -a /etc/default/camera-detection

# 2) MySQL buffer pool（默认 128M 是玩具口径）
sudo mysql -uroot -p -e "SET GLOBAL innodb_buffer_pool_size=4294967296;"
echo 'innodb_buffer_pool_size=4G' | sudo tee -a /etc/mysql/mysql.conf.d/mysqld.cnf

sudo systemctl restart camera-detection
```

> 20 台相机日增最大 1.3GB、库 2 年约 40GB，堆 2G + pool 4G 足够；报表大跨度查询也覆盖。

### 步骤 5：Nginx 反代（可选但建议）

installer 不涉及 Nginx。图片与前端均由后端 8091 直接提供，Nginx 仅用于统一 80 入口：

```nginx
server {
  listen 80;
  location / { proxy_pass http://127.0.0.1:8091; proxy_set_header Host $host; }
  client_max_body_size 20m;    # 单张图片最大 6MB，留余量
}
```

### 步骤 6：管理员与设备令牌

```bash
# 管理员初始口令 admin/123456（03_system_settings 灌入）→ 首次登录立即改密
# 设备令牌：cfg_camera_token 表，必须与相机端配置一致（缺失则上报 401）
```

### 步骤 7：验证

```bash
echo '<sudo口令>' | sudo -S env VERIFY_PASSWORD='<应用口令>' MYSQL_PASSWORD='<库口令>' \
  bash /opt/camera-detection-system/scripts/verify.sh          # 预期 32/32
bash /opt/camera-detection-system/scripts/service.sh health    # 进程/HTTP/磁盘/库/心跳
```

浏览器回归：`node docs/scripts/verify_camera_status_browser.cjs`（登录后 KPI 与产线口径）。

## 四、相机接入切换

| 项 | 操作 |
|---|---|
| 上报地址 | 相机端配置的上报 URL 改为新机 `http://<新机IP>:8091/api/v1/...`（心跳 / 图片上传 / 批量上报三端点） |
| 设备令牌 | `cfg_camera_token` 与相机端逐台核对一致 |
| 判定顺序 | 相机身份一律按 `camera_code`（现场跨产线重名），接入前先把 20 台的 `dim_camera` 档案录对（`camera_type=REAL`，**不设 REAL 的相机每小时会被当 TEST 清掉**） |
| 切换时机 | 建议停机窗口内一次性切换；旧机停写后如需保留历史，走第五节迁移 |

## 五、旧服务器数据迁移（可选）

旧机现存 7 天数据（图片 ~4k 张 / 300MB，库 37MB）。两选一：

- **A. 不迁移（推荐，若旧机数据仅测试价值）**：新机全新开始，旧机停机前手动触发一次备份留存。
- **B. 迁移**：
  ```bash
  # 旧机：导库 + 打包图片
  mysqldump --single-transaction --set-gtid-purged=OFF wms-new > dump.sql
  tar -czf images.tgz /data/camera-detection/images/defect-images
  # 新机：导库 + 解图片 + 校验行数
  mysql -uroot wms-new < dump.sql
  tar -xzf images.tgz -C /data/camera-detection/images/
  ```

## 六、部署后基线（与老服务器的差异，注意别照搬）

| 项 | 新机口径 |
|---|---|
| 内存 | 堆 2G / pool 4G（老机 16G 未显式调，默认值能跑） |
| 磁盘 | 单 1TB 数据盘：备份仍写 `/var/backups`（系统盘 vs /data，跨盘语义保留）；`IMAGE_BACKUP_MAX_GB=20` 默认不变 |
| 保留期 | 全部沿用 730/31/30 天默认，`verify.sh` 会比对 cron 与归档口径 |
| 口令 | 全新机初始 `admin/123456`，首登改密；SSH 建议直接配 key（老机口令进 auth.log 的问题不要带过去） |
| 数据起点 | 空库冷启动，`agg_*` 孤儿行、78 条历史告警等旧机遗留问题天然不存在 |
