### 3.2 优化点

原测试问题：

- 使用 `@SpringBootTest` 加载完整 Spring 上下文。
- 依赖真实 MySQL 数据和现场相机配置。
- 当前数据不存在时，接口返回 422/500，导致测试失败。
- 测试更像现场集成测试，不适合作为“接口冻结”基线。

本轮调整：

- 改为 `MockMvcBuilders.standaloneSetup(controller)`。
- 使用 Mockito mock Service 层。
- 不加载 Spring 上下文、不连接数据库、不依赖真实配置。
- 只验证 HTTP 路径、Header、请求结构、响应 code/data 等契约。

## 5. 构建脚本优化

### 修改文件

- `D:\45344\0004-软件源码\frontend\package.json`

### 修改内容

将硬编码本机 Node 路径：

```json
"dev": "\"C:\\Users\\Administrator\\AppData\\Local\\Programs\\nodejs\\current\\node.exe\" ./node_modules/vite/bin/vite.js --host 0.0.0.0"
```

调整为可移植命令：

```json
"dev": "vite --host 0.0.0.0",
"build": "vite build",
"preview": "vite preview"
```

收益：

- 换电脑后不再依赖固定用户目录。
- 与标准 npm/Vite 项目一致。
- 便于后续 CI、安装包构建脚本调用。

## 7. 本轮未做的大规模改造

为降低风险，本轮没有直接拆分大 Controller、大 Vue 页面和 SQL。原因：

1. 当前功能仍在频繁迭代，直接迁移目录容易引入回归问题。
2. 需要先建立接口契约测试和页面构建基线。
3. 大文件拆分应以模块为单位逐步推进，每次拆分后执行专项回归。
