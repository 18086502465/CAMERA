## 1. P0 —— 上线前必须修（1 项）

### 1.1 普通用户可删除管理员账号，导致系统锁死

**这是本轮最严重的发现，已用真实普通用户 token 实测确认。**

#### 现象（实测记录）

用 `role=0` 的普通用户 `test_worker` 登录取得 token 后：

| 请求 | 实际响应 | 判定 |
|---|---|---|
| `GET /api/user` | **200** | ★ 读到全部用户列表 |
| `GET /api/v1/system/settings` | **200** | ★ 读到系统设置 |
| `GET /api/logs/operation` | **200** | ★ 读到全部操作日志 |
| `GET /api/company` | **200** | ★ 读到公司配置 |
| **`DELETE /api/user/1`** | **200** | ★★ **把 admin 账号删掉了**（用户表清空） |

> 事后已恢复 admin（`admin/admin123`，实测可登录）。
> **这就是危害的证明：一个普通工人账号可以删掉唯一的管理员 → 除了直连数据库，无人能再登录。**

#### 根因

上一轮修鉴权时，`JwtRequestFilter` 已经把角色正确放进了 Spring Security 的权限集合：

```java
// JwtRequestFilter.java —— 角色映射已实现
Integer role = jwtUtil.getRoleFromToken(jwtToken);
if (role == null) { role = user.getRole(); }
UserDetails principal = new JwtUserDetails(user.getUsername(), user.getPasswordHash(), role, userId)
// 内部：role==1 → ROLE_ADMIN，role==0 → ROLE_USER
```

**但 `SecurityConfig` 从未使用它**：

```java
// SecurityConfig.java:108-109 —— 只有"是否登录"，没有"是什么角色"
).permitAll()
.anyRequest().authenticated()      // ← 普通用户和管理员一视同仁
```

且全仓库**没有** `@EnableGlobalMethodSecurity` / `@PreAuthorize` / `@Secured`（扫描结果为空）。

前端确实做了菜单隐藏（`Layout.vue` 的 `isAdmin`），但**那只是界面隐藏，不是权限控制** ——
接口本身对任何登录用户开放。

#### 影响面

**58 个管理员专属端点**（10 个 Controller）全部可被普通用户调用：

| Controller | 端点数 | 涉及操作 |
|---|---|---|
| `FinalConfigController` | 14 | 产品/缺陷类型/映射的增删改 |
| `SysUserController` | 8 | **用户的增删改、禁用、角色变更** |
| `DimWorkstationController` | 6 | 工位增删改 |
| `DimProductionLineController` | 6 | 产线增删改 |
| `SysHolidayConfigController` | 6 | 节假日增删改 |
| `SysOperationLogController` | 6 | 操作日志读取/导出 |
| `DimCompanyController` | 5 | 公司增删改 |
| `ConfigImportController` | 4 | **配置批量导入（可改全部维表）** |
| `SystemSettingsController` | 2 | **系统设置读写** |
| `CascadeController` | 1 | 级联配置读取 |

对照：74 个业务端点（看板、相机、缺陷图片、产线分析）是工人应当能访问的，无需限制。

#### 修复方案

**推荐：路径级 `hasRole`（改一处，立即生效）+ 关键方法级 `@PreAuthorize`（精确）**

**第一步 —— 在 `SecurityConfig` 收紧**（改动最小，5 分钟）：

```java
// 1) 启用方法级鉴权（写在类上）
@EnableGlobalMethodSecurity(prePostEnabled = true)

// 2) 管理类路径要求 ADMIN
.antMatchers(
    "/api/user/**",
    "/api/v1/system/settings/**",
    "/api/config-import/**",
    "/api/logs/operation/**",
    "/api/cascade/**",
    "/api/company/**",
    "/api/factories/**",
    "/api/lines/**",
    "/api/workstations/**",
    "/api/holiday/**",
    "/api/v1/config/**"
).hasRole("ADMIN")
```

> ⚠️ **注意**：`/api/user/me` 与 `/api/auth/me` 是"查自己"，必须留在 `authenticated` 段，
> 否则普通用户登录后拿不到自己的信息。改完务必实测这一条。

**第二步 —— 关键写操作加 `@PreAuthorize`**（防路径写漏）：

```java
// SysUserController —— 用户管理是最高危
@PreAuthorize("hasRole('ADMIN')")
@PostMapping
public ResultVO<SysUser> create(...) { }
```

**第三步 —— 自检脚本加一项越权检查**（把回归纳入日常）：

在 `verify-installation.ps1` 里加：
```powershell
# 越权检查：普通用户不得访问管理员接口
# 需要库里有 role=0 的账号；没有则跳过并提示
```

**第四步 —— 补一个普通用户种子账号**，让"工人视角"可被真实验证：

```sql
INSERT INTO sys_user (username, password_hash, real_name, role, is_disabled)
VALUES ('worker', '<bcrypt>', '演示工人', 0, 0);
```

#### 工作量与验证

| 项 | 工作量 |
|---|---|
| `SecurityConfig` 收紧 + `@EnableGlobalMethodSecurity` | **0.5 小时** |
| 10 个 Controller 加 `@PreAuthorize`（可只加写操作） | 2–4 小时 |
| 自检脚本加越权检查 | 0.5 小时 |
| 回归验证（普通用户 + 管理员双视角） | 0.5 小时 |

**验证方法**（本次已用同一套方法验证出问题，修复后应反向验证）：

```bash
# 普通用户 token 调管理员接口 → 应 403
TOKEN=$(登录普通用户)
curl -H "Authorization: Bearer $TOKEN" http://IP:8091/api/user          # 期望 403
curl -X DELETE -H "Authorization: Bearer $TOKEN" http://IP:8091/api/user/1 # 期望 403
# 管理员 token 调同样接口 → 应 200
```

## 3. P1 —— 代码完整性（3 项，建议排期）

### 3.1 Controller 直连 SQL：101 处 + 10 处 DDL

| Controller | 行数 | jdbcTemplate | 其中写 DDL |
|---|---|---|---|
| `LineAnalyticsController` | **1,072** | **44** | **7** |
| `FinalConfigController` | 412 | 21 | 0 |
| `SystemSettingsController` | 370 | 14 | 3 |
| `ConfigImportController` | 554 | 8 | 0 |
| 其余 23 个 | — | 14 | 0 |

**后果**：
- 无法单元测试（SQL 藏在 Controller 里）
- 改表结构时 SQL 与实体不同步（今天上午的 `image_id` 事故就是这个成因）
- `LineAnalyticsController` 单文件 1,072 行，是最需要拆分的地方

**建议**（不是一次性大重构）：

3. 其余 Controller 按使用频率排期，一次改一个

### 3.2 业务 VO 缺失：228 处直接返回 Map

`vo` 包只有 2 个类（`ResultVO` + `ExcelImportResultVO`），**没有任何业务 VO**。
228 处方法签名直接返回 `Map<String, Object>`。

**后果**：前端字段名拼错**编译期发现不了、运行期才发现**；接口文档只能靠读代码。

**建议**：不要求全量补 VO（成本高），但**新增接口必须用 VO**，
并在 `docs/api/` 里维护接口契约（已有 `接口冻结契约-v1.0-20260616.md` 的好先例）。

### 3.3 测试覆盖 11%

| 项 | 现状 |

| 测试文件 | 3 个 |
| 用例 | 8 个 |
| 覆盖 Controller | 3 / 27 = **11%** |
| 覆盖到的 | `BatchUploadController`（设备端冻结契约）、`CameraStatusHeartbeatController`、`DefectImageController` |

**好消息**：这 8 个用例保护的是**设备端冻结契约**（最不能坏的部分），这个优先级是对的。

## 4. P1 —— 易用性（4 项）

### 4.1 计划任务不自动注册：新装机器上备份/清理/巡检**都不会跑**

**实测**：全新装机后跑 `verify-installation.ps1`，**3 项计划任务全部失败**：

```
计划任务 CameraDetection-Backup        失败   未注册（运行 register-scheduled-tasks.ps1）
计划任务 CameraDetection-CleanupImages 失败   未注册
计划任务 CameraDetection-DiskUsage     失败   未注册
```

三件套脚本**随安装包发布了，但不会自动生效** —— 运维人员不主动执行一次，
系统就处于**无备份、无清理、无告警**状态，而且**没有任何地方提示这件事**
（除非他恰好跑了自检并读到失败项）。

**建议**：在 `install-service.ps1` 末尾加一段"注册计划任务"（需管理员权限，失败只告警不中断）：

```powershell
# 注册运维计划任务（失败只提示，不影响安装）
$reg = Join-Path $PSScriptRoot 'register-scheduled-tasks.ps1'
if (Test-Path $reg) {
    & $reg -InstallDir $installDir 2>&1 | ForEach-Object { Write-Host $_ }
}
```

同时在安装向导的完成页加一行提示：
「已注册运维计划任务（每日 01:00 备份 / 03:30 清理 / 每 30 分钟磁盘巡检）」。

**工作量：0.5 小时。**

### 4.2 服务名硬编码 6 处

`CameraDetectionSystem` 这个名字散落在：

1. `installer/service-wrapper/CameraDetectionService.cs`
2. `installer/scripts/install-service.ps1`
3. `installer/scripts/start-service.ps1`
4. `installer/scripts/stop-service.ps1`
5. `installer/scripts/service-status.ps1`
6. `installer/scripts/uninstall-service.ps1`
7. `installer/scripts/verify-installation.ps1`（我今天加的）
8. `installer/camera-detection-system.iss`（`UninstallDisplayIcon`）

**换服务名要改 8 个文件**，漏一个就出故障。

**建议**：加一个 `installer/service-name.txt`，脚本统一从它读；
或在每个脚本顶部加 `$serviceName = if ($env:CDS_SERVICE_NAME) {...} else {'CameraDetectionSystem'}`。

**工作量：1 小时。** 优先级不高（除非有改名需求），但属于"迟早会踩"的坑。

### 4.3 自检脚本的失败提示会误导人

**实测**：`登录接口` 这一项显示 **失败**，但 Detail 写的是 **`code:200（账号 admin）`**。

```powershell
Add-Check '登录接口' ([bool]$token) "code:200（账号 $User）"   # ← Detail 是写死的
```

Detail 无论成功失败都显示 `code:200`，**和实际情况矛盾**。运维看到"失败 + code:200"会困惑。

**另一个关联问题**：`-Password` 参数默认为空，**新装库的种子口令是 `123456`** ——
不改口令直接跑自检，登录必然失败。这本身是对的（应该提示改口令），但要**说清楚原因**。

**建议**：

```powershell
if ([bool]$token) {
    Add-Check '登录接口' $true "成功（账号 $User）"
} else {
    Add-Check '登录接口' $false "登录失败 —— 新装库默认口令为 123456，投产前必须改；可用 -Password 指定实际口令重跑"
}
```

**工作量：0.5 小时。**

### 4.4 前端样式体系缺失：535 行 CSS 变量没人用，634 处硬编码色值

| 项 | 实测 |
|---|---|
| `src/styles/global.css` | **535 行，0 处 import**（定义了整套 CSS 变量，等于没写） |
| 硬编码 6 位色值 | **634 处，分布在 37 个 .vue** |
| 零消费者组件 | 8 个（含 `BaseEmptyState` / `BaseErrorState` / `BaseLoadingState` 各 9 行） |
| 零消费者 API 模块 | 1 个（`src/api/final-config.js`，14 个函数全无用） |

**后果**：改主题色要改 37 个文件；`BaseEmptyState` 这类基础组件存在却不用，
每个页面各写一套空状态 —— **用户看到的是"有的页面有加载态、有的没有"的不一致体验**。

**建议**（按性价比）：
1. **先 import `global.css`**（1 行）—— 让 CSS 变量生效
2. `BaseEmptyState` / `BaseErrorState` / `BaseLoadingState` 三个 9 行组件接进页面（半天，**体验提升明显**）
3. 硬编码色值分批替换为 CSS 变量（634 处，建议按页面分批，不追求一次性）
4. 删掉 `final-config.js` 与其余零消费者组件（死代码清理）

### 6.1 Windows 全新装机端到端（今天首次实测，通过）
