相机实时状态上报接口协议
1. 接口概述
本接口用于相机系统每 5 秒高频上报实时运行状态及累计计数。主要用于平台实时看板展示、设备在线监控及即时异常告警。与“批量历史数据上报”接口互补，本接口侧重时效性。
项目	内容
接口路径	/api/v1/camera/status/heartbeat
请求方式	POST
数据格式	application/json; charset=utf-8
幂等性	基于 cameraName + timestamp 更新最新状态
超时时间	建议设置 5 秒（轻量级数据）
________________________________________
2. 请求报文
2.1 请求头 (Header)
参数	必填	说明
Content-Type	是	application/json
Authorization	是	Bearer {token} (认证令牌)
X-Device-Id	是	相机设备编号
2.2 请求体 (Body)
{
  "cameraName": "正面检测",
  "productName": "008 小护-K8",
  "timestamp": "2025-12-30 16:34:05",
  "cameraStatus": 1,
  "recognizeCount": 1500,
  "correctCount": 1450,
  "abnormalCount": 50,
  "cpuUsage": 45.5,
  "memoryUsage": 60.2,
  "temperature": 35.5,
  "errorMessage": ""
}
2.3 字段映射说明
模块	JSON 字段	类型	说明	枚举/格式
基础信息	cameraName	String	相机名称	例：正面检测
	productName	String	当前生产产品	例：008 小护-K8
	timestamp	String	上报时间	yyyy-MM-dd HH:mm:ss
状态信息	cameraStatus	Integer	相机运行状态	0:停止, 1:运行, 2:故障, 3:待机
计数信息	recognizeCount	Integer	识别总数 (累计)	当前会话累计识别数量
	correctCount	Integer	识别正确数 (累计)	当前会话累计 OK 数量
	abnormalCount	Integer	识别异常数 (累计)	当前会话累计 NG 数量
资源监控	cpuUsage	Double	CPU 使用率	百分比 (0-100)
	memoryUsage	Double	内存使用率	百分比 (0-100)
	temperature	Double	设备温度	摄氏度 (℃)
异常信息	errorMessage	String	故障错误信息	状态为 2 时填写
________________________________________
3. 响应报文
3.1 成功响应 (HTTP 200)
{
  "code": 200,
  "message": "success",
  "data": {
    "serverTime": "2025-12-30 16:34:05",
    "nextInterval": 5000,
    "configVersion": "v1.2.0"
  }
}
3.2 失败响应 (HTTP 4xx/5xx)
{
  "code": 400,
  "message": "Invalid cameraStatus",
  "data": null
}
3.3 状态码定义
代码	含义	处理建议
200	成功	状态已更新
400	参数错误	检查状态枚举值
401	未授权	检查 Token
403	设备禁用	相机未被平台授权
500	服务器错误	联系运维

4. 服务端处理逻辑
4.1 状态更新策略
数据类型	存储策略	说明
实时状态	Redis Cache	Key: camera:status:{cameraName}，TTL: 15 秒
计数数据	数据库/Redis	可选持久化，主要用于看板展示
离线判定	定时任务	超过 15 秒未收到心跳，标记为离线
4.2 状态机流转
┌─────────────────────────────────────────────────────────┐
│                    相机端每 5 秒上报                       │
│                  (状态 + 计数 + 资源)                      │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   平台接收心跳                           │
│              更新 Redis 缓存状态 (TTL 刷新)                 │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   异常判断                               │
│    1. 状态==2 (故障) → 触发告警通知                       │
│    2. 计数异常 (负数/突变) → 记录日志                     │
│    3. 资源过高 (CPU>90%) → 记录预警                       │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   返回配置信息                           │
│    可下发最新配置版本号，提示相机是否需要更新配置          │
└─────────────────────────────────────────────────────────┘

5. 业务规则与注意事项
5.1 上报频率控制
场景	上报间隔	说明
正常运行	5 秒	标准心跳频率
故障状态	5 秒	保持上报以便监控故障详情
网络波动	指数退避	失败后 5s→10s→20s 重试
5.2 计数一致性
1.	累计值：recognizeCount、correctCount、abnormalCount 建议为当前会话累计值（开机或重置后累加）。
2.	校验逻辑：recognizeCount ≈ correctCount + abnormalCount (允许 1 以内误差)。
3.	重置信号：若相机端重置了计数器，建议在上报中携带 resetFlag: true，通知平台清零统计。
5.3 离线判定
•	平台侧应启动定时任务，检查 Redis 中状态键的 TTL。
•	若 key 过期，自动将相机状态更新为 离线 (Status: 9)。
•	前端看板根据此状态显示灰色/红色图标。
5.4 性能建议
1.	轻量级：本接口不包含详细缺陷数据，仅包含计数，确保响应速度 < 100ms。
2.	并发：支持多相机并发上报，避免锁竞争。
3.	压缩：一般不需要 GZIP，除非字段大幅扩展。

6. 附录
6.1 相机状态枚举 (cameraStatus)
值	状态	颜色	说明
0	停止	灰色	相机程序未运行或手动停止
1	运行	绿色	正常检测中
2	故障	红色	发生异常，需干预
3	待机	黄色	程序运行但无产品触发
9	离线	黑色	平台超过 15 秒未收到心跳
6.2 错误码参考
错误码	说明	解决方案
STATUS_001	无效的状态码	检查 cameraStatus 枚举
COUNT_001	计数逻辑错误	检查总数是否等于 OK+NG
TIME_001	时间戳过期	检查相机系统时间
