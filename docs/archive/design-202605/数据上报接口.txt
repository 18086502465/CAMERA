数据上报接口
1. 接口概述
本接口用于相机系统每分钟批量上报检测数据数组。每次请求包含多条记录（建议 2 秒间隔一条，每分钟约 30 条），平台将进行批量入库处理。
项目	内容
接口路径	/api/v1/camera/inspection/batch-upload
请求方式	POST
数据格式	application/json; charset=utf-8
幂等性	基于 startTime + cameraName 唯一索引，重复提交将触发更新
超时时间	建议设置 30 秒（批量数据处理耗时较长）

3.4 状态码定义
代码	含义	处理建议
200	全部成功	所有记录已入库
207	部分成功	检查 details 中失败记录
400	参数错误	检查 JSON 格式或必填项
401	未授权	检查 Token
413	数据过大	减少单次上报记录数
500	服务器错误	联系运维

4. 服务端处理逻辑
4.1 自动处理字段
以下字段无需前端传递，由服务端自动处理：
字段	实体字段	处理逻辑
主键 ID	id	数据库自增，响应中返回
非法 NG 数	illegalNgCount	服务端计算：ngCount - ∑(所有缺陷字段)
数据来源	dataSource	服务端默认置为 batch_api_push
创建时间	createTime	服务端自动填充 (当前时间)
更新时间	updateTime	服务端自动填充 (当前时间)
是否处理	isProcessed	服务端默认置为 0 (未处理)
4.2 批量处理流程
┌─────────────────────────────────────────────────────────┐
│                    相机端每分钟上报                       │
│                  (约 30 条记录/批次)                       │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   平台接收批量请求                        │
│              校验 dataList 非空且≤100 条                   │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   遍历每条记录                           │
│    1. 校验时间格式                                      │
│    2. 计算 illegalNgCount                               │
│    3. 填充 dataSource、isProcessed 等系统字段            │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐
│                   批量入库处理                           │
│    1. 检查唯一索引 (startTime + cameraName)              │
│    2. 存在则 UPDATE，不存在则 INSERT                     │
│    3. 记录每条处理结果                                   │
└────────────────────┬────────────────────────────────────┘
                     │
                     ▼
┌─────────────────────────────────────────────────────────┐

└─────────────────────────────────────────────────────────┘

5. 业务规则与注意事项
5.1 上报频率建议
场景	上报间隔	每条记录间隔	单次记录数
正常生产	每分钟 1 次	2 秒	30 条
高速生产	每分钟 2 次	1 秒	30 条
低速生产	每分钟 1 次	5 秒	12 条
5.2 数据一致性要求
1.	时间连续性：dataList 中各记录的 startTime 应连续递增，间隔建议 2 秒。
2.	累计值递增：totalCount、okCount、ngCount 应为累计值，后续记录应≥前序记录。
3.	清零记录：换班或重置时，recordType=1，累计值从 0 重新开始。
5.3 重试机制
场景	处理策略
网络超时	本地缓存，下次批次合并上报
部分失败 (207)	仅重试失败记录，成功记录不重复上报
全部失败	完整批次重试，最多 3 次
唯一索引冲突	视为成功 (数据已存在)，不重试
5.4 性能建议
1.	单次上限：建议 dataList 不超过 100 条，避免请求超时。
2.	请求超时：客户端超时时间建议设置为 30 秒。
3.	并发控制：同一设备同一时间只允许一个批次在处理中。
4.	数据压缩：如网络带宽有限，可启用 GZIP 压缩。

后腰腹	backWaistGlue...	backWaistDefect...
内外层	innerOuterGlue...	innerOuterDefect...

6.2 错误码参考
错误码	说明	解决方案
DATA_001	dataList 为空	检查上报逻辑
DATA_002	记录数超限	减少单次上报数量
TIME_001	时间格式错误	统一为 yyyy-MM-dd HH:mm:ss
TIME_002	时间不连续	检查记录间隔
DUP_001	唯一索引冲突	视为成功，无需重试
