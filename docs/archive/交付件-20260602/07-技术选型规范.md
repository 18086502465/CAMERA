# 技术选型规范

## 1. 选型原则

- 优先使用成熟稳定、社区活跃、运维成本低的技术。
- 单机 Windows 部署优先，减少现场依赖。
- 前后端分离开发，生产部署合并为单服务。
- 接口、配置、日志、数据目录保持可运维。

## 2. 前端技术

| 技术 | 当前版本/范围 | 选型理由 |
|---|---|---|
| Vue | 3.x | 组件化、生态成熟、适合中后台。 |
| Vite | 5.x | 构建速度快，配置简单。 |
| Element Plus | 2.x | 表格、表单、弹窗、分页等中后台组件完善。 |
| ECharts | 5.x | 工业看板图表能力成熟。 |
| Pinia | 3.x | Vue 官方推荐状态管理。 |
| Axios | 1.x | HTTP 请求封装稳定。 |

## 3. 后端技术

| 技术 | 当前版本/范围 | 选型理由 |
|---|---|---|
| Java | 8 | 与当前代码和现场环境兼容。 |
| Spring Boot | 2.7.15 | 稳定 LTS 风格，支持内嵌 Tomcat 和 fat jar。 |
| Spring MVC | 2.7.x | REST API 开发成熟。 |
| Spring Security | 5.x | 支持 JWT 和接口鉴权。 |
| MyBatis-Plus | 3.5.3.1 | 简化 CRUD 和分页。 |
| Druid | 1.2.x | MySQL 连接池和监控能力。 |
| Apache POI | 5.2.4 | Excel 模板与导入导出。 |
| Lombok | 1.18.x | 减少样板代码。 |

## 4. 数据库技术

| 技术 | 说明 |
|---|---|
| MySQL 8.0 | 单机部署，字段、索引、事务能力满足当前需求。 |
| utf8mb4 | 支持中文、特殊符号。 |
| InnoDB | 支持事务和行级锁。 |

## 5. 部署技术

| 技术 | 用途 |
|---|---|
| Spring Boot fat jar | 后端 + 前端静态资源统一运行。 |
| Windows Service | 开机自启动和后台运行。 |
| C# 服务包装器 | 启动 jar、指定外部配置、写服务日志。 |
| Inno Setup | 生成 Windows 安装程序。 |
| PowerShell | 构建、安装、卸载、启动、停止脚本。 |

## 7. 版本约束

- 不建议在当前阶段升级到 Spring Boot 3，因为会涉及 Java 17、Jakarta 包名迁移。
- 不建议现场电脑依赖 Node 运行，生产环境只运行 Spring Boot 服务。
- MySQL 建议固定 8.0，避免 5.7 与 8.0 SQL/字符集差异。

## 8. 选型风险与规避

| 风险 | 影响 | 规避 |
|---|---|---|
| Java 8 逐步老旧 | 后续安全和生态升级受限 | P1/P2 规划 Java 17 + Spring Boot 3 升级。 |
| 当前 JWT/设备 Token 简化 | 安全风险 | 增加设备 Token 表和签名机制。 |
| 单机 MySQL | 高可用不足 | 当前满足现场单机，后续可扩展主从/备份策略。 |
| 前端 chunk 体积偏大 | 首屏加载略慢 | 后续做路由级拆包和 manualChunks。 |
| Windows 服务包装器自研 | 需维护 | 保持代码简洁；也可评估 WinSW/NSSM。 |

## 9. 新增技术准入规则

- 新依赖必须说明用途、版本、License、替代方案。
- 不得引入长期无人维护或安全风险高的依赖。
- 前端依赖必须能通过 Vite 构建。
- 后端依赖必须兼容 Java 8 和 Spring Boot 2.7。
- 安装包依赖必须能离线交付或明确安装步骤。
