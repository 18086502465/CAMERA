# 业务需求规格说明

## 1. 文档目的

本文定义“相机检测系统”的业务目标、用户角色、功能范围、业务规则、数据口径、非功能要求和验收标准，作为研发、测试、交付、运维的统一依据。

## 2. 项目背景

工厂生产线部署多台检测相机，对产品进行视觉检测。系统需要接收相机状态、检测数据、缺陷图片，并为工厂负责人、产线管理人员、系统管理员提供实时看板、质量统计、图像记录、配置维护和操作追溯能力。

## 3. 业务目标

1. 让工厂负责人在统一看板中了解产线质量与异常情况。
2. 让现场人员及时发现相机故障、上传中断、资源过高、缺陷高发等风险。
3. 让质量人员按工厂、产线、工位、相机、产品、班次维度追溯检测记录和缺陷图片。
4. 让管理员维护工厂、产线、工位、相机、用户等基础配置。
5. 支持相机设备通过标准接口上报心跳、检测数据和缺陷图片。
6. 支持 Windows 单机部署，目标电脑安装 MySQL 后即可运行。

## 4. 用户角色

| 角色 | 权限定位 | 主要任务 |
|---|---|---|
| 工厂负责人 | 查看全局质量和产线表现 | 查看相机状态、产线总览、缺陷统计、良率分析、图像记录。 |
| 质量/生产人员 | 查看与追溯 | 按筛选条件查询检测记录、缺陷图片、异常告警。 |
| 系统管理员 | 配置和运维 | 管理工厂、产线、工位、相机、用户、配置导入、操作记录。 |
| 相机设备 | 数据上报主体 | 上报心跳、检测批量数据、缺陷图片和 metadata。 |

## 5. 功能范围

### 5.1 登录与用户

- 支持用户登录、注册、当前用户信息查询。
- 前端通过 JWT Token 保存登录态。
- 角色：`1=管理员`，`0=普通用户`。
- 管理员可进入系统配置页，普通用户限制配置能力。

### 5.2 顶部全局筛选

- 支持工厂、产线、工位级联筛选。
- 默认工厂范围应避免误过滤新上传数据，当前实现默认可展示全部工厂。
- 全局筛选影响看板、统计、图像记录、相机状态等页面。

### 5.3 五个核心 Tab

| Tab | 默认顺序 | 业务定位 |
|---|---:|---|
| 相机状态 | 1 | 默认进入，关注相机运行状态、上传状态、资源指标、最近图像。 |
| 产线总览 | 2 | 以产线负责人视角查看产量、良率、缺陷、告警、趋势。 |
| 缺陷统计 | 3 | 查看缺陷总量、高中低严重度、类型、位置、趋势、明细。 |
| 良率分析 | 4 | 查看良率趋势、工位排行、产品/班次对比。 |
| 图像记录 | 5 | 按相机聚合展示最近缺陷图片、历史图像、缺陷框 metadata。 |

### 5.4 相机状态

- 展示相机卡片、相机上传表格、最近缺陷图片。
- 支持搜索、状态筛选、异常优先排序。
- 相机运行状态来自心跳字段 `cameraStatus`。
- 上传状态由最后上传时间/心跳时间派生。
- 状态规则：
  - 运行状态：`0=停止`、`1=运行`、`2=故障`、`3=待机`、`9=离线`。
  - 心跳/上传时间 ≤30 秒：正常/在线。
  - 30~120 秒：延迟。
  - >120 秒：离线。
- 告警规则：
  - `cameraStatus=2` 为故障，告警级别 `CRITICAL`。
  - CPU>90%、内存>90%、温度>70℃ 为 `WARNING`。

### 5.5 产线总览

产线总览不再展示相机工作状态，应从工厂负责人视角关注：

- 今日总产量、OK 数、NG 数、综合良率。
- 产线良率趋势、小时/30分钟粒度走势。
- 缺陷数量和高危缺陷数量。
- 工位质量排行与短板工位。
- 产品/品牌维度良率对比。
- 当前未处理异常数量。
- 班次表现对比。

### 5.6 缺陷统计

- 查看缺陷总览：总缺陷、高危、中危、低危。
- 查看缺陷趋势、类型分布、位置热力图、时段分布、区域分布。
- 支持按工厂、产线、工位、产品、班次、时间范围筛选。
- 支持从缺陷明细追溯图片和相机。

### 5.7 良率分析

- 查看总良率、趋势、工位排行、产品对比。
- 数据来源包含检测批量上报和按 30 分钟聚合事实表。
- 支持产线、工位、产品、班次维度分析。

### 5.8 图像记录

- 按相机聚合展示最近图片。
- 最近上传图片优先展示。
- 支持展开历史记录分页，分页长度支持 5、10、20、50。
- 点击图片后展示文件名、拍摄时间、上传时间、缺陷类型、严重度、坐标、面积。
- 图片解析失败时，应展示产品化失败原因和处理建议。

### 5.9 系统配置

P0 包含：

- 工厂管理。
- 产线管理。
- 工位管理。
- 相机管理。
- 用户管理。
- 操作记录。
- 配置导入：工厂、产线、工位、相机整体配置导入，支持全量导入和增量导入。

P1 可继续考虑：

- 品牌管理合并进聚合配置页。
- 缺陷分类合并进聚合配置页。

### 5.10 配置管理规则

- 工厂 > 产线 > 工位 > 相机 为层级递进关系。
- 一个工位允许绑定多台相机。
- 相机唯一标识以 `cameraCode/deviceId` 为准，`cameraName` 作为展示名。
- 相机所属产线/工位只允许系统配置维护，心跳不修改归属关系。
- 删除和修改必须进行依赖校验和风险提示。
- 工厂/产线/工位/相机管理不需要状态属性展示。

### 5.11 相机上报协议范围

最终保留三类数据来源：

| 数据来源 | 接口 |
|---|---|
| 检测批量上报 | `POST /api/v1/camera/inspection/batch-upload` |
| 相机心跳上报 | `POST /api/v1/camera/status/heartbeat` |
| 缺陷图片上传 | `POST /api/v1/defect-images/upload` |

### 5.12 数据清理

清理策略需可配置，默认建议：

| 数据 | 默认保留 | 动作 |
|---|---:|---|
| 缺陷图片文件 | 30 天 | 删除文件和图片记录。 |
| 缺陷框 metadata | 90 天 | 归档或保留统计摘要。 |
| 检测历史明细 | 90 天 | 归档到历史表。 |
| 30 分钟事实 | 1 年 | 保留。 |
| 操作日志 | 180 天 | 清理。 |

## 6. 非功能需求

| 类型 | 要求 |
|---|---|
| 可用性 | 单机部署可稳定运行，Windows 服务开机自启动。 |
| 性能 | 常规页面查询 3 秒内返回；相机上报接口避免长事务阻塞。 |
| 安全 | 设备上报需要 Bearer Token 和 `X-Device-Id`；3306 默认不对外开放。 |
| 可维护 | 前后端分层清晰，接口统一返回格式，配置外置。 |
| 可追溯 | 用户操作写入操作日志；图片上传保留 batch、file、box metadata。 |
| 可部署 | 发布包内置前端和 JRE，目标电脑安装 MySQL 即可运行。 |
| 可扩展 | 后续支持后端分页、导出、更多配置项合并。 |

## 7. 验收标准

1. 安装后访问 `http://localhost:8091` 能打开系统。
2. 刷新 `/camera-status`、`/dashboard`、`/stats/images`、`/system/config` 不 404。
3. 相机心跳上报后，相机状态页能更新状态、资源、产品、故障信息。
4. 缺陷图片批量上传后，图像记录和相机状态页能展示最近图片和缺陷框信息。
5. 检测批量上报后，缺陷统计和良率分析能查询到对应数据。
6. 配置管理支持工厂、产线、工位、相机、用户分页查询和维护。
7. 删除工厂/产线/工位/相机时有依赖校验和风险提示。
8. 操作记录页能查询用户操作日志。
9. 构建脚本可生成发布目录和安装 exe。
10. 安装包可安装 Windows 服务，并开机自启动。
