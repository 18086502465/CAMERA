# 前端设计规范

## 1. 技术栈

| 项 | 选型 |
|---|---|
| 框架 | Vue 3 |
| 构建 | Vite 5 |
| 路由 | Vue Router 4，history 模式 |
| 状态 | Pinia |
| UI | Element Plus |
| 图表 | ECharts |
| HTTP | Axios |

## 2. 目录规范

```text
frontend/src
├─ api                 后端接口封装，每类资源一个文件
├─ components          可复用组件
├─ router              路由定义和路由守卫
├─ stores              Pinia 状态
├─ styles              全局样式
├─ utils               通用工具，如 request/auth/message
└─ views               页面级组件
```

## 3. 路由规范

- 使用 `createWebHistory()`。
- 发布后由 Spring Boot `SpaFallbackController` 支持刷新路由。
- 页面路由必须配置清晰的 `name` 和 `meta.title`。
- 管理员页面使用 `meta.requiresAdmin=true`。
- 默认首页为 `/camera-status`。

核心路由：

| 路由 | 页面 | 说明 |
|---|---|---|
| `/login` | Login | 登录。 |
| `/register` | Register | 注册。 |
| `/camera-status` | CameraStatusView | 默认 Tab。 |
| `/dashboard` | Dashboard | 产线总览。 |
| `/stats/defects` | DefectsView | 缺陷统计。 |
| `/stats/yield` | YieldView | 良率分析。 |
| `/stats/images` | ImagesView | 图像记录。 |
| `/system/config` | ConfigView | 系统配置。 |

## 4. Tab 与 Layout 规范

- 五个核心 Tab 固定在顶部，不随页面下滚消失。
- Tab 顺序：相机状态、产线总览、缺陷统计、良率分析、图像记录。
- 顶部筛选包含：班次、工厂、产线、工位、系统配置、用户菜单。
- 筛选条件变化后，页面组件应自动刷新数据。
- 默认工厂不应导致新上传图片被误过滤。

## 5. API 调用规范

- 统一使用 `src/utils/request.js`。
- `baseURL=/api`。
- 前端 API 文件只封装请求，不写复杂业务逻辑。
- 请求函数命名：`getXxxList`、`createXxx`、`updateXxx`、`deleteXxx`。
- 页面内必须处理 loading、empty、error 三种状态。
- 所有分页接口统一传：`page`、`size`。
- 分页长度统一支持：`5`、`10`、`20`、`50`。

## 6. 组件设计规范

### 6.1 页面组件

- 页面组件放在 `views`。
- 页面组件负责：筛选、分页、弹窗状态、调用 API。
- 不在页面组件中写跨页面复用逻辑。

### 6.2 业务组件

- 复用组件放在 `components`。
- 如 `CameraImageRecords.vue` 负责图像记录卡片、历史表格、图片弹窗。
- 组件暴露 `reload()` 时，应通过 `defineExpose` 明确声明。

### 6.3 状态组件

- 空状态、异常状态、加载状态统一使用 `EmptyState.vue` 或同等封装。
- 空状态文案要说明“为什么没有数据”和“下一步怎么做”。
- 图片解析失败要展示：失败原因、处理建议、文件名、接口返回错误码。

## 7. 表格规范

- 所有配置管理表格默认分页 10 条。
- 支持 pageSize：5、10、20、50。
- 表格操作列固定右侧。
- 删除操作必须二次确认。
- 存在依赖时禁止直接删除，并展示依赖数量和处理建议。
- 状态字段使用 Tag 样式，不使用纯文本。

## 8. 表单规范

- 新增/编辑使用弹窗或抽屉。
- 必填项必须在前端校验并展示明确错误。
- 工厂、产线、工位、相机为层级递进选择，不允许跳级创建错误归属。
- 工厂/产线/工位/相机管理不展示状态字段。

## 9. 图像记录规范

- 按相机聚合展示。
- 卡片按最新上传图片优先排序。
- 每个相机默认展示最近 5 张图片。
- 历史记录支持分页。
- 点击图片展示大图、metadata 和缺陷框信息。
- 图片 URL 必须经后端接口访问，不直接暴露本地磁盘路径。

## 10. 图表规范

- ECharts 图表必须在容器尺寸变化时 resize。
- KPI 数字应有单位和口径说明。
- 缺陷严重度颜色：高危红色，中危橙色，低危蓝色。
- 良率趋势优先使用折线图，工位排行使用柱状图。

## 11. 样式规范

- 使用 Element Plus 设计语言。
- 卡片圆角、阴影、间距保持统一。
- 主色：蓝色系；异常：红色系；警告：橙色系；正常：绿色系。
- 1280px 以下需要响应式降级，卡片网格变为双列或单列。
- 避免在页面中堆叠过多强对比色。

## 12. 前端质量要求

- 构建必须通过：`npm run build`。
- 关键页面刷新不 404。
- 控制台不应出现未捕获异常。
- 接口失败必须提示，不允许静默失败。
- 新页面必须补充：路由、菜单/Tab、API 封装、空状态、分页、异常态。
