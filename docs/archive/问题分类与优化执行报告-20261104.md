### P0-1　`install.sh` 把占位符当成数据库口令，新机安装后服务启动即挂

| 项 | 内容 |
|---|---|
| **问题描述** | 上一轮安全改造把 `application.yml` 的 `password:` 改成了 `${MYSQL_PASSWORD}` 占位符，但 `install.sh` 第 307 行仍用 `sed` 从该文件提取口令：<br>`sed -n 's/.*password:[[:space:]]*\([^[:space:]#]*\).*/\1/p'`<br>该正则会把**占位符本身**提取出来。实测：<br>`sed ... installer/templates/application.yml` → 输出 `${MYSQL_PASSWORD}`（字符串字面量） |
| **影响范围** | **所有新机部署**。install.sh 会把字面量 `${MYSQL_PASSWORD}` 写进 `/etc/default/camera-detection`，systemd 注入该字面量 → Druid 数据源认证失败 → **服务启动即挂**，日志报 `Access denied for user 'root'`，极难联想到是安装脚本取错了口令 |
| **优先级判定理由** | 阻断性缺陷 + 影响全部新机交付。当前线上机侥幸正常，只是因为上一轮改造时手工注入了真口令 |
| **具体改动** | ① 口令来源改为三级优先级：**环境变量 → 现场既有 `/etc/default` → 交互式读取**；<br>② 显式识别 `${...}` 占位符形态并判定为「未配置」，绝不采信；<br>③ 第 4 节整体重写 `/etc/default` 前，先捕获既有 `MYSQL_PASSWORD` / `ADMIN_USER` / `ADMIN_PASSWORD`（原实现会连带抹掉管理员口令，与第 8c 节注释声称的"保留"不符）；<br>④ **顺带修复**：第 8c 节的 `sed` 删除了 `JWT_SECRET` 却只写回 `MYSQL_PASSWORD` → 重装后 JWT 密钥消失，`JwtUtil` 无兜底默认值 → 服务启动失败 |
| **验证方式** | 新增 `docs/scripts/test_install_password_source.sh`（5 组用例 / 11 项断言），隔离复刻口令提取与 8c 节 sed 逻辑，实测证明修复前后行为差异 |
| **回归检查点** | ① 用例 3 确认占位符被识别为未配置；② 用例 4 确认 `sed` 删除后 `JWT_SECRET` 被写回；③ 用例 5 确认 `install.sh` 不再从 `application.yml` 提取口令；④ 服务器 `service.sh config-check` → 密钥已设置、无明文口令 |

### P0-2　心跳与图片通道的相机匹配优先级错误，重名相机数据互相覆盖

| 项 | 内容 |
|---|---|
| **问题描述** | 两条写 `camera_status` 的路径匹配顺序不一致：<br>① `CameraStatusServiceImpl.saveCameraStatus` —— **先按 `camera_name` 匹配、`LIMIT 1`**，编号仅兜底；<br>② `DefectImageServiceImpl.updateCameraLatestImage` —— `eq(cameraName).or().eq(cameraCode).or().eq(cameraCode)` **无优先级 OR 链 + `LIMIT 1`**，命中行完全不确定；<br>③ 而同文件的 `findCameraForAlert` 却是 code-first（口径已不一致）<br>**实测已确认重名存在**：`camera_status` 里 `CV1_Cam1` / `CV2_Cam1` **各 2 行**（ZK54 的 `DA8119487`/ws7 与 ZK23 的 `DA8119489`/ws23） |
| **影响范围** | 所有重名相机。`LIMIT 1` 无 `ORDER BY` 时命中哪行由执行计划决定 → 一旦设备上报名与配置名一致，心跳会写进**另一台相机**的行，表现为该相机的心跳时间/计数被别的设备覆盖，**现场极难察觉** |
| **优先级判定理由** | 数据损坏风险。当前现场**尚未发生**（设备上报中文名"正面检测"≠ 配置名 `CV1_Cam1`，实际走了编号兜底分支），但只要现场新增一台同名相机或改配置名即触发 |
| **具体改动** | ① 统一改为 **`camera_code` 优先**（`camera_code` 上有唯一索引 `uk_camera_code`，是设备的天然身份标识），名称仅在无编号时兜底；<br>② 名称兜底时**必须唯一**：命中多行则**拒绝写入并记 WARN**，宁可失败也不静默写错行；<br>③ `updateCameraLatestImage` 的无优先级 OR 链改为同样的确定性匹配 |
| **验证方式** | 用 ZK23 真实相机编号 `DA8119489` + 重名 `CV1_Cam1` 发心跳，看值落到哪一行 |
| **回归检查点** | 实测：`id=23` 的 `recognize_count` 精确变为 `888888`，**`id=9` 完全未被污染**（保持 1224）；无编号 + 重名时返回"缺少设备ID"，不误写 |
