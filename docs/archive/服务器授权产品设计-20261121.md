# 服务器授权产品设计（4 步精简流程版）

> 设计日期：2026-11-21 ／ 版本：V1.0（产品设计稿）  
> 上游决策：`服务器授权使用流程与交付规划-20261121.md` §0（9 项决策）  
> 真源协议：`docs/服务器授权设计.md`（签名/状态机）；本文定义**流程、两个交付物格式、两个产品形态**  
> 代码基线：`LicenseController`、`LicenseService`、`LicenseSigner`、`LicenseView.vue`、`gen_license.py`

## 0. 一页概览

```
① 商务定档          ② 客户下载机器码包        ③ 研发生成授权包        ④ 客户导入生效
单号+相机数+期限  →  平台页面 → machine-*.zip  →  签发工具 → license-*.zip  →  平台页面拖入
                    （发给研发）                 （发给客户）              （自动 reload）
```

| 角色 | 只做一件事 | 产物 |
| --- | --- | --- |
| 商务 | 定档：合同相机数、期限、客户名，生成单号 | `LIC-20261121-001` |
| 客户 | 页面点「下载机器码包」→ 发给研发；收到授权包后拖回页面 | `machine-05144C536FC17D9E-20261121-165812.zip` |
| 研发 | 用签发工具**导入机器码包**，填单号/期限/相机数/策略，生成授权包 | `license-LIC-20261121-001.zip` |
| 平台 | 生成本机机器码包；校验并导入授权包；到期提示 | 授权生效 |

**设计原则**（按上游决策收敛）：
1. **不手抄机器码**——客户只用点一个按钮，避免 16 位码抄错、截图失真；
2. **不手工改文件**——研发只拖入 zip、填 4 个参数，工具负责签名与打包；
3. **导入前先预览**——避免把别的客户的授权装上来；
4. **零停机**——导入即生效（自动 reload），不重启服务；
5. **不阻断生产**——到期策略默认 `warn`，只提示不停线。

## 1. 端到端流程

### 1.1 正常路径

| 步 | 责任方 | 动作 | 系统行为 | 校验点 |
| - | --- | --- | --- | --- |
| 1 | 商务 | 定档并生成单号 | ERP/邮件下发（本产品不含商务系统） | 单号唯一 |
| 2 | 客户 | 授权页点「下载机器码包」 | `GET /api/license/machine-code-package` → zip | 包内 `machine-info.json` 机器码 = 页面显示值 |
| 3 | 客户→研发 | 邮件/微信传 zip | — | 不传截图、不手抄 |
| 4 | 研发 | 工具拖入 zip，填单号/期限/相机数/策略 | 读 zip → 校验 → 签名 → 打包 | 工具 `inspect` 自检通过 |
| 5 | 研发→客户 | 回传 `license-*.zip` | — | 文件名含单号与机器码 |
| 6 | 客户 | 授权页拖入 zip → 预览 → 确认导入 | `preview` → `import` → 落盘 + reload | 状态变 `VALID`，剩余天数正确 |
| 7 | 客户 | 截图/导出结果回传商务 | 页面显示导入结果卡 | 单号、到期日、相机上限三项一致 |

### 1.2 异常分支

| 场景 | 系统行为 | 客户/研发处置 |
| --- | --- | --- |
| 机器码包下载失败（指纹全部不可读） | 返回 `400` + 「本机读不到硬件指纹，请检查 `/sys/class/dmi/id/product_uuid` 与 `/etc/machine-id`」 | 提单给研发，改用手工机器码模式（`--machine`） |
| 研发用错客户密钥 | 客户导入时验签失败，**原授权不受影响** | 研发按台账核对密钥指纹后重签 |
| 授权包与现场机器不符 | 预览即拦截，提示双方机器码 | 确认是否装错机器 / 是否需要重装签发 |
| 相机上限低于现场实际台数 | 预览给黄条警告，导入需勾选「确认降档」 | 商务确认是否扩容 |
| 授权包损坏/传输被截断 | zip 结构校验失败，明确报「包不完整，请重新发送」 | 重传 |
| 客户误传自己做的包 | 签名不符，拒绝 | 说明只能由厂商签发 |

## 2. 两个交付物格式（冻结协议）

### 2.1 机器码包 `machine-<机器码>-<yyyyMMdd-HHmmss>.zip`

| 文件 | 必需 | 内容 |
| --- | --- | --- |
| `machine-info.json` | ✅ | 结构化，签发工具直接读 |
| `machine-info.txt` | ✅ | 人读版，方便贴邮件/微信 |
| `README.txt` | ✅ | 「把整个 zip 发给研发，不要截图、不要手抄机器码」 |
| `MANIFEST.sha256` | ✅ | 上述文件逐行 `<sha256>  <文件名>`，防传输损坏 |

`machine-info.json`：

```json
{
  "schema": "camera-detection-machine-info/1",
  "machineCode": "05144C536FC17D9E",
  "fingerprintSource": "machine-id",
  "hostname": "camd-prod-01",
  "appVersion": "1.0.0",
  "product": "产线缺陷在线AI检测",
  "generatedAt": "2026-11-21T16:58:12+08:00",
  "cameraCount": 24,
  "currentLicense": {
    "licenseId": "LIC-20261112-153000",
    "status": "VALID",
    "expireAt": "2029-11-12",
    "maxCameras": 200
  },
  "orderHint": "LIC-20261121-001"
}
```

| 字段 | 用途 | 说明 |
| --- | --- | --- |
| `machineCode` | 绑定签发 | 16 位大写，工具据此填 `--machine` |
| `fingerprintSource` | 排障 | `product_uuid`/`machine-id`/`dbus`/`board_serial`，换机重签时判断根因 |
| `cameraCount` | 档位建议 | 研发据此判断「签 30 台是否够」，避免签完立刻顶格 |
| `currentLicense` | 续期参考 | 让研发知道原来给到哪天、多少台 |
| `orderHint` | 可选 | 客户能填单号就填，工具自动带出 |

**不含任何敏感信息**：无 DB 口令、无 `JWT_SECRET`、无 `LICENSE_SECRET`、无图片路径。

### 2.2 授权包 `license-<单号>-<机器码>.zip`

| 文件 | 必需 | 内容 |
| --- | --- | --- |
| `license.lic` | ✅ | 签名票据，**平台唯一消费的文件** |
| `order.json` | ✅ | 单号/客户/期限/相机数/策略/签发人（供人对账，不参与验签） |
| `授权说明.txt` | ✅ | 导入三步 + 到期后怎么办 + 联系方式 |
| `MANIFEST.sha256` | ✅ | 含 `license.lic` 的 sha256，工具与平台双端校验 |

`order.json`：

```json
{
  "schema": "camera-detection-license-order/1",
  "orderNo": "LIC-20261121-001",
  "customer": "XX汽车",
  "machineCode": "05144C536FC17D9E",
  "issuedAt": "2026-11-21",
  "expireAt": "2027-11-21",
  "maxCameras": 30,
  "expiredMode": "warn",
  "issuedBy": "研发-张三",
  "toolVersion": "2.0.0",
  "licSha256": "9f2c…"
}
```

### 2.3 载荷变更（`license.lic` 内）

| 变更 | 说明 |
| --- | --- |
| 新增 `expiredMode` | 取值 `warn`/`readonly`/`block`；`version` 提升为 `2` |
| 向后兼容 | `LicenseSigner` 的 `ObjectMapper` 已设 `FAIL_ON_UNKNOWN_PROPERTIES=false` → **旧 jar 读新授权会忽略该字段、回退配置文件**，不会报错 |
| 生效优先级 | `license.expiredMode` > `/etc/default` 的 `LICENSE_EXPIRED_MODE` > 默认 `warn` |
| 版本过新 | 若 `version > 2`，导入时拒绝并提示「授权由更新版本工具签发，请先升级平台」 |

> 为什么策略要进载荷：客户现场不能改策略（改配置就能把 `readonly` 变 `warn`），而商务卖的是「到期后怎么处理」。策略进签名载荷后，配置只能作为缺省值。

## 3. 产品一：平台「服务器授权」页面

### 3.1 信息架构

| 区块 | 内容 | 现状 |
| --- | --- | --- |
| ① 状态区 | 状态胶囊（正常/即将到期/已到期/未授权/无效/机器不符/试用中）+ 剩余天数 + 到期日 + 策略说明 | 已有横幅，需补 `TRIAL` 与策略来源 |
| ② 机器码区 | 16 位机器码大字 + 来源 + **「下载机器码包」按钮** | 仅显示 + 复制 |
| ③ 导入区 | 拖拽/选择 zip → **预览摘要** → 确认导入 → 结果卡 | 单步直传 `.lic` |
| ④ 详情区 | 单号/客户/签发日/到期日/相机上限/策略/文件路径/文件更新时间 | 已有表格 |
| ⑤ 说明区 | 授权性质（合规提示、不防逆向、不阻断）、续期找谁、换机怎么办 | 部分已有 |

### 3.2 机器码区交互

| 元素 | 规格 |
| --- | --- |
| 机器码展示 | `mono` 字体 18px、字距 2px、分组显示 `0514 4C53 6FC1 7D9E`；旁注「不可逆推硬件序列号」 |
| 指纹来源 | 徽标显示 `machine-id`，悬浮提示「重装系统会变码」 |
| 下载按钮 | 主按钮「下载机器码包（.zip）」；点击即触发浏览器下载，文件名 `machine-<码>-<时间>.zip` |
| 失败提示 | 机器码为 `null` → 按钮禁用 + 红字说明原因与检查路径 |
| 提示语 | 「把整个 zip 发给研发，不要截图或手抄机器码（16 位错一位就签错机器）」 |

### 3.3 导入区交互（两步式，核心设计）

**第一步：预览**（不落盘）

| 项 | 规格 |
| --- | --- |
| 入口 | 拖拽区 + 「选择文件」，接受 `.zip`（兼容 `.lic`，老流程仍可用） |
| 上传 | `POST /api/license/preview`（multipart），返回摘要，**绝不写盘** |
| 摘要卡 | 单号、客户、本机机器码 vs 包内机器码（一致打 ✅）、到期日、剩余天数、相机上限（vs 现场实际台数）、到期策略（白话：只提示/停设备上报/只留授权页）、签发日、签发人 |
| 阻断项 | 见 §3.5 错误码；有阻断则「确认导入」按钮禁用并显示原因 |
| 警告项 | 相机上限 < 现场台数 → 黄条 + 需勾选「我确认按该上限降档」 |
| 二次校验 | 预览有效期 5 分钟（后端缓存 token），超时需重新选包，避免预览与导入不是同一个文件 |

**第二步：确认导入**

| 项 | 规格 |
| --- | --- |
| 入口 | 摘要卡底部「确认导入」 |
| 上传 | `POST /api/license/import`（multipart + `previewToken`），后端重算摘要并比对，防止两次文件不一致 |
| 落盘顺序 | 验签 → 机器预检 → 配额检查 → 备份旧文件为 `license.lic.bak-<ts>` → 原子替换 → reload → 返回新状态 |
| 结果卡 | 绿色「授权已生效」+ 新状态四要素（单号/到期日/相机上限/策略）+ 「复制摘要」按钮（便于回传商务） |
| 失败 | 红色卡 + 错误码 + 一句话处置建议；**原授权保持可用**（需在文案中明说，避免客户恐慌） |

### 3.4 状态与文案（含到期策略）

| 状态 | 胶囊 | 主文案 | 副文案 |
| --- | --- | --- | --- |
| `VALID` | 绿 | 授权正常 | 剩余 N 天，到期日 YYYY-MM-DD |
| `EXPIRING` | 黄 | 授权即将到期 | 剩余 N 天，请提前 30 天申请续期 |
| `TRIAL` | 蓝 | 试用中 | 试用剩余 N 天，到期后功能仍可用但会持续提示 |
| `EXPIRED` | 红 | 授权已到期 | 功能不受影响，请尽快续期（策略：只提示/停设备上报/只留授权页） |
| `MISSING` | 橙 | 未安装授权 | 请下载机器码包申请授权；试用期内不阻断 |
| `INVALID` | 红 | 授权文件无效 | 签名不符或文件损坏，请联系研发重签 |
| `MACHINE_MISMATCH` | 红 | 授权与本机不符 | 包内机器码 X，本机 Y；重装系统后需重签 |

> 「不影响功能」必须在 `EXPIRED` 文案里**显式写出来**——这是决策 1/7 的对外承诺，也是避免现场误判停线的关键。

### 3.5 导入错误码（前后端统一）

| 错误码 | 触发 | 提示 | 是否阻断 |
| --- | --- | --- | --- |
| `LIC-ZIP-001` | 不是 zip / CRC 失败 | 包不完整或已损坏，请让研发重新发送 | ✅ |
| `LIC-ZIP-002` | 包内无 `*.lic` | 这不是授权包，请确认文件名以 `license-` 开头 | ✅ |
| `LIC-ZIP-003` | 多个 `*.lic` | 包内有多份授权，请让研发重新打包 | ✅ |
| `LIC-ZIP-004` | 条目含 `../`、绝对路径、子目录 | 包结构非法，已拒绝 | ✅ |
| `LIC-ZIP-005` | 体积 > 256KB 或条目 > 16 | 包异常偏大，请确认来源 | ✅ |
| `LIC-FILE-001` | 签名不符 | 授权与该客户密钥不匹配，请联系研发核对 | ✅ |
| `LIC-FILE-002` | 载荷损坏 / 字段非法 | 授权文件损坏，请重新签发 | ✅ |
| `LIC-FILE-003` | `version > 2` | 授权由更新版本签发，请先升级平台 | ✅ |
| `LIC-MACHINE-001` | 机器码不符 | 该授权绑定 X，本机 Y | ✅ |
| `LIC-QUOTA-001` | `maxCameras` < 现场台数 | 上限低于现场实际台数，需勾选确认 | ⚠️ 需确认 |
| `LIC-ORDER-001` | `order.json` 单号与 `license.lic` 不一致 | 单号与票据不一致（仅提示，不阻断） | ⚠️ 警告 |

| 方法 | 路径 | 权限 | 说明 |

## 4. 产品二：签发工具（研发侧）

### 4.1 形态

| 形态 | 说明 | 适用 |
| --- | --- | --- |
| **CLI**（主） | 单文件 `issue_license.py`，Python 3.8+ 仅标准库 | 批量、脚本化、可审计 |
| **GUI**（辅） | 同目录 `issue_license_gui.py`，Tkinter 单窗口；可用 PyInstaller 打成 `签发工具.exe` | 商务/售前也能自己签 |

> 工具**只存在于厂商侧**，绝不进客户交付包（上游 P0-1 / LIC-08）。打包脚本需断言包内无 `issue_license*`、无 `gen_license.py`。

### 4.2 CLI 命令

```bash
# ① 一步签发（从客户机器码包直接读，不用手抄）
python issue_license.py issue \
    --machine-zip machine-05144C536FC17D9E-20261121-165812.zip \
    --order LIC-20261121-001 \
    --customer "XX汽车" \
    --months 12 \
    --max-cameras 30 \
    --expired-mode warn \
    --secret-file ./secrets/xxqiche.key \
    --out license-LIC-20261121-001.zip

# ② 发给客户前自检（验签 + 机器码 + 期限 + 包结构）
python issue_license.py inspect license-LIC-20261121-001.zip

# ③ 台账（追加到 CSV，供商务对账）
python issue_license.py ledger --out ledger.csv
```

| 参数 | 必填 | 取值 | 说明 |
| --- | --- | --- | --- |
| `--machine-zip` | 与 `--machine` 二选一 | 客户包路径 | **首选**；自动读机器码、客户名提示、现场相机数 |
| `--machine` | 二选一 | 16 位大写 | 兜底（客户给的是截图/手抄） |
| `--order` | ✅ | `LIC-YYYYMMDD-NNN` | 商务单号，进 `order.json` 与文件名 |
| `--customer` | ✅ | 文本 | 进载荷，页面上会显示 |
| `--months` / `--expire` | ✅ 二选一 | `12` / `2027-11-21` | `months` 按签发日加月，`expire` 精确到期日（含当天） |
| `--max-cameras` | ✅ | `30` / `-1` | `-1` 不限；`0` 或 `<-1` 报错 |
| `--expired-mode` | 否 | `warn`(默认)/`readonly`/`block` | 到期策略，写入载荷 |
| `--secret-file` | ✅ | 密钥文件 600 | **禁止命令行传明文密钥**（会进 shell history） |
| `--out` | 否 | 路径 | 缺省 `license-<单号>.zip` |

### 4.3 GUI 布局（单窗口，5 个字段）

```

│  相机上限  [30        ] 台（-1 不限）         │

│  ────────────────────────────────────────    │
│  客户密钥  [ 选择 secrets/xxqiche.key ]      │
```

| 交互 | 规格 |
| --- | --- |

| 期限下拉 | 6/12/24/36 个月 + 「自定义到期日」；实时显示到期日 |
| 相机上限 | 默认 = 现场台数 × 1.2 向上取整（避免顶格），可改 |
| 策略下拉 | 三项带白话：只提示(warn) / 到期停设备上报(readonly) / 到期只留授权页(block) |
| 生成 | 校验必填 → 签名 → 写 zip → 自动 `inspect` → 展示摘要；失败不产生文件 |
| 密钥记忆 | 只记路径不记内容；上次目录优先 |

### 4.4 密钥管理（一客户一密钥）

| 项 | 规格 |
| --- | --- |
| 存放 | 厂商侧 `secrets/<customer-slug>.key`，权限 600，目录不进版本库 |
| 生成 | `python issue_license.py keygen --customer xxqiche` → 32 字节 hex |
| 指纹 | `sha256(secret)[:8]`，写台账，**便于核对而不用暴露密钥** |
| 注入 | 打客户专属包时写入 `config/customer.env`，`install.sh` 装到 `/etc/default/camera-detection` |
| 轮换 | 仅限新客户首装；已交付客户不轮换（轮换=该客户全部授权失效） |

### 4.5 台账 `ledger.csv`

`orderNo,customer,machineCode,expireAt,maxCameras,expiredMode,issuedAt,issuedBy,secretFp,licSha256,note`

| 用途 | 说明 |
| --- | --- |
| 商务对账 | 「这个客户签了几次、哪天到期」 |
| 到期提醒 | 按 `expireAt` 排序，30 天内高亮 |
| 争议举证 | 与客户回传的 `order.json` 逐字段比对 |

## 6. 到期表现（承接决策 7）

| 场景 | 表现 |
| --- | --- |
| `EXPIRING`（≤30 天） | 页面顶部细横幅，可关闭，不弹窗 |
| `EXPIRED` / 试用到期 | **非模态**大卡片常驻可关；**每次页面点击重新弹出**；不阻断点击、不拦路由、不拦写请求 |
| `MISSING`（试用期内） | 仅横幅 + 授权页提示，不弹窗 |
| `MISSING`（超试用期） | 同 `EXPIRED` 弹窗，文案为「未安装授权」 |
| 策略 `readonly`/`block` | 由后端闸门执行；页面明确提示「当前策略会拒绝设备上报」 |

> 实现约束（务必遵守）：禁止用带遮罩的 `el-dialog`，否则点击被遮罩吃掉，用户必须先关窗才能操作，与「不影响功能」矛盾。

## 7. 安全与合规边界

| 项 | 设计 |
| --- | --- |
| zip 解析 | 只读内存、限制 256KB / 16 条目 / 单条 128KB；拒绝绝对路径、`..`、子目录、符号链接；只取根目录唯一 `*.lic` |
| 密钥 | 不进命令行（`--secret-file`）、不进台账（只存指纹）、不进机器码包 |
| 机器码包内容 | 无口令、无密钥、无图片路径；`hostname` 可关（`--no-hostname`） |
| 不可防逆向 | 如实写明：授权用于**合规留痕与到期提醒**，不构成技术强制（承接决策 2 / R-02） |
| 非安全边界 | 授权不约束设备接入；设备侧安全靠网络隔离（承接决策 6 / R-01） |
| 审计 | 导入/预览失败均记 WARN + 操作人；V1.2 补 `fact_operation_log` |
