## 0. 决策记录（9 项，已拍板）

| # | 待确认项 | 决策 | 对方案的直接影响 |
| - | --- | --- | --- |
| 1 | 授权定位 | **运维合规提示** | 不做功能停用：`expired-mode` 维持 `warn`，撤销初稿「切 `readonly`」的建议；合规性靠**提示可见 + 台账 + 验收断言**，不靠停线 |
| 2 | 是否接受「不防逆向」 | **接受** | **取消 ECDSA（原 LIC-16）**，继续 HMAC-SHA256；对客户如实写明「可挡改日期/换机/过期，挡不住反编译」，不承诺不可破解 |
| 3 | 密钥体系 | **一客户一密钥** | 新增「客户专属发行包」机制：打包时注入该客户密钥，安装脚本写入 `/etc/default`；厂商维护密钥矩阵。**切换密钥会让存量授权失效**，必须按 §8.2 的迁移顺序执行 |
| 4 | 是否按模块分档 | **无需** | **取消 `features` 判定（原 LIC-14）**；商务口径固定为「相机数 × 期限 × 单机绑定」三维，`features` 保留为展示字段 |
| 5 | 是否需要试用 | **需要，2 个月（60 天）** | 新增 `TRIAL` 状态 + 首启起算 + 落库防重启重置；到期后退化为软提示，不阻断 |
| 6 | 8091 是否收窄、设备令牌是否配齐 | **不能收窄，不配齐** | **撤销原 P0-3**，转为「已接受残余风险 R-01」；明确授权闸门只约束管理端使用范围，**不构成设备接入安全边界** |
| 7 | 到期表现 | **大弹窗 + 每次点击都弹「已到期」 + 不影响功能** | 新增前端全局非模态浮层（原方案无此能力）；**禁止用带遮罩的 `el-dialog`**，否则会吃掉点击、违背「不影响功能」 |
| 8 | 交付实施方 | **客户自行安装** | SOP 改为客户自助 + 远程支持 + 自检报告回传；**签发工具绝不能随包**这条从「建议」升为硬约束；需补客户版安装手册与自检报告模板 |
| 9 | 授权粒度 | **按服务器机器码** | `enforce-machine=true` 固定；**取消多租户/多工厂（V2.0 主线）**；换机/重装系统必须重签，交付培训必须讲清 |

## 1. 结论先行（决策后的口径）

| # | 结论 |
| - | --- |
| 1 | **不是从零规划**：2026-11-12 已落地完整离线 License 子系统（协议、HMAC 签名、机器指纹、8 态状态机、三种过期策略、相机配额、运行时闸门、前端授权页、21 个单测、设计文档与运维 SOP）。 |
| 2 | **现场实测**：`VALID`、剩余 1087 天、`maxCameras=200`、机器码 `05144C536FC17D9E`（来源 `machine-id`）、`expiredMode=warn`。这是一张**用内置默认密钥自签的 3 年期试点授权**，不是商务交付授权。 |
| 3 | **定位已明确为「运维合规提示」**，因此本方案**不追求强约束**：到期不阻断、不防逆向、不按模块分档。要解决的是三件事——**签发权不落客户机**、**到期提示足够显眼**、**交付与验收留痕**。 |

## 4. 端到端使用流程（现状，未改）

| 阶段 | 动作 | 关键事实 |
| --- | --- | --- |
| A 出厂安装 | `install.sh` 生成 `/etc/default/camera-detection` | `JWT_SECRET` 每机随机 64 hex；模板**未写** `LICENSE_SECRET`/`LICENSE_EXPIRED_MODE` → 现场用 jar 内置固定密钥 + 默认 `warn` |
| B 取机器码 | `gen_license.py fingerprint` 或 `/system/license` 页、`GET /api/license/machine-code` | 现场来源 `machine-id` → **重装系统会变码** |
| C 厂商签发 | `gen_license.py issue --customer … --expire … --max-cameras … --machine …` + `inspect` | `--features` 预留未生效；`--secret` 必须与服务器一致 |
| D 客户导入 | 页面上传（内存验签 → 绑定预检 → 备份旧文件 → 原子替换）或手工投放 + `/reload` | 验签失败不动任何字节 |
| E 运行期 | 每次 `getState()` 按当天重算；`EXPIRING` 阈值 30 天；文件 mtime 30s 重载 | `warn` 下 `EXPIRED` 也不阻断业务 |
| F 到期/续期/换机 | 续期不需重取码；换机/重装需重取码 | 详见 §8.8 |

### 8.2 一客户一密钥：客户专属包与迁移顺序（决策 3 落地）

**新增脚本** `installer/linux/scripts/make_customer_bundle.sh`：

```bash
# 厂商侧执行，产出客户专属包（不是通用包）
./make_customer_bundle.sh --customer "XX汽车" --secret "$(openssl rand -hex 32)" \
    --out dist-customer/XX汽车-1.0.0.tar.gz
# 内部步骤：解开通用包 → 排除 scripts/gen_license.py → 注入 config/customer.env(600)
#          → 重打包 → 断言包内无 gen_license.py、有 customer.env → 打印密钥指纹（不打印密钥）
```

`install.sh` 增量逻辑：

1. 若存在 `config/customer.env`，读取 `LICENSE_SECRET` 并写入 `/etc/default/camera-detection`（640 root:root）；
2. 写完后 `shred -u config/customer.env`（避免明文长期留存，客户仍可从 `/etc/default` 读到——这是决策 2 已接受的边界）；
3. 无该文件时回退 jar 内置默认密钥，并打 `WARN`「本包未绑定客户密钥，请确认是否为通用包」。

**★ 迁移顺序（现场已有一张内置密钥签的 3 年期授权，顺序错会直接 `INVALID`）**：

| 步 | 动作 | 校验点 |
| --- | --- | --- |
| 1 | 用**新密钥**为该客户机器码签发新 `.lic`（到期日不晚于原授权） | `gen_license.py inspect` 通过 |
| 2 | 先上传新 `.lic`（此时服务器仍用旧密钥 → 验签失败，验证会拒绝且**不覆盖原文件**） | 确认原授权仍 `VALID`，证明原子替换有效 |
| 3 | 写入 `LICENSE_SECRET` 到 `/etc/default` → `systemctl restart` | 启动日志密钥指纹变化 |
| 4 | 再上传新 `.lic` → `POST /api/license/reload` | `GET /api/license` → `VALID` 且 `licenseId` 为新单号 |
| 5 | 删除旧 `.lic` 备份中的过期件，保留一份 `.bak-*` | 备份目录只剩新授权 |

> 第 2 步是刻意做的**负向验证**：先证明「错密钥不会破坏现有授权」，再切密钥。若跳过，一旦第 4 步失败将同时失去新旧授权。

### 8.3 角色与职责（客户自装）

| 角色 | 职责 |
| --- | --- |
| 商务 / 产品 | 定档（相机数、期限）、生成授权单号、到期提醒 |
| 厂商签发人 | 保管密钥矩阵、按机器码签发、`inspect` 自检、登记台账 |
| 厂商支持工程师 | 交付客户专属包、远程指导安装、审核回传的自检报告、异常时远程排查 |
| 客户实施 | 按手册安装、跑 `verify.sh` 回传报告、取机器码、上传授权、签验收单 |
| 客户运维 | 保管 `.lic`、关注到期提示、提前 30 天申请续期、换机时提供新码 |

### 8.4 客户自助安装 SOP（10 步）

| # | 步骤 | 责任方 | 产出 / 验收点 |
| - | --- | --- | --- |
| 1 | 商务定档 + 生成授权单号 `LIC-CUS-yyyyMMdd-xxx` | 商务 | 单号 + 合同相机数/期限 |
| 2 | 生成该客户 `LICENSE_SECRET`，登记密钥矩阵（**不发客户明文**） | 厂商签发人 | 密钥指纹记录 |
| 3 | 打客户专属包（剔签发工具、注入密钥、补设计文档） | 研发 | 包内断言：无 `gen_license.py`、有 `customer.env` |
| 4 | 客户解压执行 `sudo ./scripts/install.sh`（按手册填 DB 口令） | 客户实施 | 服务 `active`、`HTTP 200` |
| 5 | 跑 `sudo ./scripts/verify.sh`（45 项）+ 回传输出 | 客户实施 | 全绿截图/日志 |
| 6 | 取机器码：`GET /api/license/machine-code` 或授权页复制 | 客户实施 | 16 位大写码回传 |
| 7 | 厂商签发 + `inspect` 自检 + 发 `.lic`（邮件/受控下载） | 厂商签发人 | `.lic` + 单号 |
| 8 | 客户在 `/system/license` 上传 → 状态变 `VALID` | 客户实施 | `GET /api/license` 截图 |
| 9 | 跑 `verify.sh --delivery` 四项断言 + 生成自检 JSON 回传 | 客户实施 | `licenseSelfCheck.json` 全 `pass` |
| 10 | 双方确认验收单 + 台账归档 + 到期前 30 天提醒 | 商务 + 客户 | 签字单 + 台账条目 |

> 与初稿差异：第 4~9 步责任方由「我方实施」改为「客户实施 + 我方远程审核」；因此**手册必须是客户能独立照着做的**（含截图与常见报错），`verify.sh` 必须输出可粘贴回传的结构化结果。

### 8.5 到期全局提示规格（决策 7 落地）

| 项 | 规格 |
| --- | --- |
| 组件 | 新增 `frontend/src/components/LicenseNotice.vue`，挂在 `App.vue` 根部 |
| 数据源 | `GET /api/license`；启动拉一次，之后每 10 分钟刷新；路由切换时若缓存超 60s 则刷新 |
| 触发状态 | `EXPIRED`（含试用到期）、`MISSING`、`INVALID`、`MACHINE_MISMATCH`；`EXPIRING`（≤30 天）只显示顶部细横幅，**不弹窗** |
| 形态 | **非模态**大卡片：宽 560px、居中偏上、红色标题「授权已到期」+ 客户名 / 到期日 / 剩余天数 / 续期联系方式 / 「继续使用」按钮 |
| **必须非模态** | 禁用 `el-dialog` 默认遮罩（`modal=false` + `lock-scroll=false`），或自绘 `position:fixed` 卡片（外层 `pointer-events:none`，面板 `pointer-events:auto`）。**带遮罩会吃掉点击，用户必须先关窗才能操作，违背「不影响功能」** |
| 重现规则 | `document.addEventListener('click', handler, true)` 捕获阶段：若已到期且面板未显示 → 显示；面板内部点击不重复触发（`event.target.closest('.license-notice')`）；同一次点击只处理一次 |
| 不阻断 | 不 `preventDefault`、不 `stopPropagation`、不拦路由、不拦写请求；`expired-mode` 保持 `warn`，后端零行为变化 |
| 关闭 | 允许关闭（点按钮/ESC/右上角），**但下一次页面点击会再次弹出**；不做「本次会话不再提示」 |
| 登录页 | 未登录时只显示顶部横幅 + 登录成功后首屏弹一次，避免遮挡登录表单与验证码 |
| 可访问性 | `role="alertdialog"`、`aria-live="polite"`、ESC 关闭 |
| 性能 | 组件本身不新增轮询请求；状态走内存缓存，点击路径零网络 |

### 8.6 试用 60 天规格（决策 5 落地）

| 项 | 规格 |
| --- | --- |
| 状态 | `LicenseStatus` 新增 `TRIAL`（置于 `VALID` 之前，避免影响 `isUsable()` 的严重度语义） |
| 起算 | 首次启动且无 `.lic` 时，写 `sys_system_setting`：`license.trial.start = yyyy-MM-dd\|machineCode`；**重启不重置** |
| 期限 | 60 天；剩余 ≤15 天 → `TRIAL` + `daysLeft` 告警色；到期 → `EXPIRED` + `trial=true` |
| 限制 | 试用期同样受相机配额约束，默认 `license.trial.max-cameras: 30`（可配） |
| 与正式授权 | 存在有效 `.lic` 时忽略试用；上传正式授权后试用记录保留但不再参与判定 |
| 展示 | 授权页显示「试用中，剩余 N 天」；到期后走 §8.5 弹窗，文案为「试用期已结束」 |
| 重置风险 | 清库/换盘可重置 → 归入 R-04，不额外加固 |
| 交付区分 | 试用与正式**同一程序包**，只靠「有无 `.lic`」区分；试用包密钥仍为该客户专属，避免试用客户拿到通用密钥 |

### 8.7 商务口径（决策 4 + 9）

| 维度 | 档位 | 载荷字段 | 是否可约束 |
| --- | --- | --- | --- |
| 相机数 | ≤30 / ≤100 / ≤200 / 不限 | `maxCameras` | ✅ 已生效（唯一资源维度） |
| 期限 | 1 年 / 3 年 / 远期 | `expireAt` | ✅ 已生效 |
| 服务器 | **单机绑定（固定）** | `machineCode` | ✅ 已生效 |
| 功能模块 | **不分档**（全部功能一致） | `features` 仅展示 | ⛔ 决策 4 关闭 |
| 试用 | 60 天 | `TRIAL` 状态 | 🔧 V1.1 落地 |
| 服务 | 续期次数、换机次数 | 走合同 + 台账 | 🔧 V1.2（LIC-15） |

> 报价与合同只写「相机数 × 期限 × 单机绑定」，**不要写模块差异**，避免交付时无法兑现。

### 8.8 续期 / 换机 / 扩容

| 场景 | 操作 | 重新取码 | 停机 | 台账动作 |
| --- | --- | --- | --- | --- |
| 续期 | 同机器码、同 `maxCameras`、新 `expireAt` 签发 → 上传覆盖 | 否 | 否 | 记新单号与到期日 |
| 扩容 | 同机器码、更大 `maxCameras` → 覆盖 | 否 | 否 | 更新相机上限 |
| 换机 / 重装 | 取新机器码重签；旧授权立即失效 | **是** | 否 | 旧码作废、新码生效 |
| 换密钥 | **只在新客户首装时发生**；已交付客户不轮换 | — | — | 轮换需整批重签，禁止随意操作 |
| 紧急恢复 | 临时 `license.enabled=false` 并重启（仅厂商授权下操作） | 否 | 是 | 24h 内恢复并记录原因 |

### 8.9 验收断言与已知限制（决策 6 + 8）

`verify.sh --delivery` 新增四项断言（**不改变现有 45 项生产自检口径，避免产线误停**）：

| # | 断言 | 失败含义 |
| - | --- | --- |
| 1 | `status ∈ {VALID, EXPIRING, TRIAL}` | 未装授权 / 签名不符 / 机器码不符 |
| 2 | `machineCode` == 验收单登记值 | 装错机器或取错码 |
| 3 | `maxCameras` == 合同值 | 签错档位 |
| 4 | `licenseFile` 存在且属主为服务账号、权限 ≤644 | 授权文件放错位置或权限异常 |

输出 `licenseSelfCheck.json`（含四项 `pass/fail` + 状态快照，**不含密钥**），供客户回传存档。

**验收单必须写明的已知限制**（对应 §6.2）：

1. 授权为**合规提示**性质，到期后系统仍可用，界面持续提示；
2. 授权不构成技术强制，不能防止反编译或自行签发；
3. 授权覆盖管理端使用范围，**不作为设备接入安全边界**；
4. 授权绑定本机机器码，重装系统/更换主板需重新签发；
5. 试用期 60 天，可通过重装环境重置（不作为合同约束依据）。
