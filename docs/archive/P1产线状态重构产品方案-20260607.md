# P1 产线状态重构产品方案（2026-06-07）

## 1. 背景

当前主 Tab 暂时只保留“相机状态”和“图像记录”。后续需要恢复并重构“产线状态/产线总览”能力，但新页面不再展示相机工作状态，而是从工厂负责人和产线负责人视角展示产线经营与质量状态。

核心诉求：

1. 查询产线维度的 OK 数、NG 数、总检测数、良率、NG 率。
2. 各种异常类型由系统配置维护，而不是写死在前端。
3. 页面根据配置的异常类型动态生成筛选项、表格列和统计图。
4. 支持图表报表配置和生成，便于后续按工厂/产线/工位/产品多维分析。

## 2. 页面定位

页面名称建议：

```text
产线状态
```

页面路径建议：

```text
/line-status
```

Tab 位置建议：

1. 相机状态
2. 图像记录
3. 产线状态（P1 恢复）

> 当前 P0 仍只保留两个主 Tab。P1 开发完成后再恢复“产线状态”Tab。

## 3. 关注对象

### 3.1 工厂负责人关注

- 今天所有产线总检测量。
- OK 数 / NG 数。
- 总体良率。
- NG 率是否超阈值。
- 哪条产线异常最多。
- 哪种异常类型增长最快。
- 哪个产品/班次质量波动最大。

### 3.2 产线负责人关注

- 当前产线实时状态。
- 当前班次检测总数、OK 数、NG 数。
- 最近 30 分钟异常趋势。
- TOP 异常类型。
- TOP 异常工位。
- 当前需要优先处理的问题。

## 4. 数据来源

| 数据 | 来源接口 | 说明 |
|---|---|---|
| 检测总数 | `/api/v1/camera/inspection/batch-upload` | 检测统计上报 |
| OK 数 | `/api/v1/camera/inspection/batch-upload` | 正确识别 / OK 统计 |
| NG 数 | `/api/v1/camera/inspection/batch-upload` | 异常识别 / NG 统计 |
| 异常类型 | 系统配置 | 动态维护异常类型 |
| 缺陷图片 metadata | `/api/v1/defect-images/upload` | 图片、缺陷框、严重度、缺陷类型 |
| 工厂/产线/工位 | 系统配置 | 维度过滤与归属关系 |
| 产品 | 检测上报 `productName` + 品牌/产品配置 | 可映射产品维度 |

## 5. 异常类型配置设计

### 5.1 配置入口

系统配置中新增或增强：

```text
系统配置 > 异常类型配置
```

### 5.2 配置字段

| 字段 | 说明 |
|---|---|
| 异常编码 | 唯一编码，例如 `SCRATCH` |
| 异常名称 | 页面展示名称，例如“划痕” |
| 所属区域 | 可选，例如“内装 / 前腰腹 / 后腰腹” |
| 严重度默认值 | HIGH / MEDIUM / LOW |
| 颜色 | 图表和标签颜色 |
| 是否启用 | 停用后不参与筛选和动态列 |
| 是否计入 NG | 默认是 |
| 排序 | 控制页面列和筛选项顺序 |
| 说明 | 业务解释 |

### 5.3 页面动态规则

页面加载时读取启用的异常类型配置：

```text
enabled = true
order by sort_order asc
```

动态生成：

- 异常类型筛选按钮。
- 产线表格异常列。
- 异常分布图 legend。
- 趋势图 series。
- 报表配置可选指标。

## 6. 产线状态页面结构

### 6.1 顶部筛选

- 日期范围。
- 班次。
- 工厂。
- 产线，多选。
- 工位，多选。
- 产品。
- 异常类型，多选，动态来自配置。
- 只看 NG。
- 只看异常增长。

### 6.2 KPI 区

| KPI | 说明 |
|---|---|
| 检测总数 | 当前筛选条件下总检测数 |
| OK 数 | 当前筛选条件下 OK 数 |
| NG 数 | 当前筛选条件下 NG 数 |
| 良率 | OK / 总数 |
| NG 率 | NG / 总数 |
| 最高异常类型 | 当前数量最高的异常类型 |
| 风险产线数 | NG 率超阈值的产线数量 |

### 6.3 产线状态表

固定列：

```text
产线名称
工厂
当前产品
班次
检测总数
OK数
NG数
良率
NG率
TOP异常
风险等级
```

动态列：

```text
{异常类型1}数量
{异常类型2}数量
{异常类型3}数量
...
```

动态列来自异常类型配置。

### 6.4 图表区

默认图表：

1. OK / NG 趋势图。
2. 异常类型分布图。
3. 产线 NG 率排行。
4. 工位异常 TOP10。
5. 产品质量对比。

### 6.5 报表配置区

支持配置：

| 配置项 | 可选值 |
|---|---|
| 图表类型 | 折线图 / 柱状图 / 饼图 / 堆叠柱状图 / 表格 |
| 维度 | 时间 / 产线 / 工位 / 产品 / 异常类型 |
| 指标 | 检测总数 / OK数 / NG数 / 良率 / NG率 / 各异常类型数量 |
| 时间粒度 | 10分钟 / 30分钟 / 小时 / 班次 / 天 |
| 筛选条件 | 工厂 / 产线 / 工位 / 产品 / 异常类型 |

## 7. 后端接口建议

### 7.1 异常类型配置接口

```http
GET /api/v1/config/defect-types?enabled=true
POST /api/v1/config/defect-types
PUT /api/v1/config/defect-types/{id}
DELETE /api/v1/config/defect-types/{id}
```

### 7.2 产线状态聚合接口

```http
GET /api/v1/line-status/overview
GET /api/v1/line-status/table
GET /api/v1/line-status/trend
GET /api/v1/line-status/defect-distribution
GET /api/v1/line-status/report
```

### 7.3 请求参数建议

```text
factoryId
lineIds
stationIds
productName
shift
timeStart
timeEnd
defectTypes
metrics
groupBy
chartType
page
size
```

## 8. 数据库建议

### 8.1 异常类型配置表

```text
dim_defect_type
```

建议字段：

| 字段 | 说明 |
|---|---|
| defect_type_id | 主键 |
| defect_code | 异常编码 |
| defect_name | 异常名称 |
| defect_area | 所属区域 |
| severity_default | 默认严重度 |
| color | 展示颜色 |
| is_enabled | 是否启用 |
| is_ng | 是否计入 NG |
| sort_order | 排序 |
| remark | 说明 |
| create_time / update_time | 时间 |

### 8.2 聚合表建议

```text
agg_line_quality_30min
agg_line_defect_type_30min
agg_station_defect_type_30min
```

目的：避免页面每次直接扫描明细表，提高报表性能。

## 10. 需要后续确认的问题

1. 异常类型是否完全以系统配置为准，还是需要与相机算法输出做映射？
2. `batch-upload` 是否已经能上报每种异常类型的数量？如果不能，需要从图片 metadata 聚合补齐。
3. 良率阈值、NG 率阈值是否按产线/产品分别配置？
4. 产线状态页是否要支持导出 Excel？
5. 图表配置是否需要保存为用户个人视图？
