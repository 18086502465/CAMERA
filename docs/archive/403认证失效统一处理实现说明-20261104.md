# 403 未授权 / 登录态失效 —— 统一处理实现说明

**日期**：2026-11-04
**问题来源**：现场反馈 `/api/cascade/all` 返回 403，页面显示 `Request failed with status code 403`，用户无从下手
**服务器**：10.2.77.72（Hik-Vision，Ubuntu 24.04.5 LTS）

---

## 一、问题定位与根因

### 1.1 现象

浏览器控制台可见：

```
GET /api/cascade/all    403 Forbidden
{"timestamp":"2026-11-04 16:09:24","status":403,"error":"Forbidden","path":"/api/cascade/all"}
```

页面显示「相机状态加载失败」。

### 1.2 根因（实测复现，非推测）

**前端**：`frontend/src/utils/request.js` 的响应拦截器**只处理 401**，403 直接 `Promise.reject` 透传给页面：

```js
if (error.response && error.response.status === 401) {
  clearToken()
  window.location.href = '/login'
}
```

**后端**（更关键）：实测三种场景的响应**完全无法区分**：

| 场景 | 改造前状态码 | 响应体 | 响应头 |
|---|---|---|---|
| 无 token | **403** | `{"status":403,"error":"Forbidden","path":"..."}` | 无 `WWW-Authenticate` |
| 伪造/过期 token | **403** | 同上 | 无 `WWW-Authenticate` |
| 已登录但角色不足 | **403** | 同上 | 无 `WWW-Authenticate` |

Spring Security 2.7 在未配置 `AuthenticationEntryPoint` 时，对未认证请求返回 403（而非 401），
且不携带 `WWW-Authenticate` 头 —— 这与「权限不足」的 403 **完全同形**。

**结论**：前端仅凭响应无法判断该跳登录页还是提示权限不足。
若一律跳登录，管理员点了个需要 ADMIN 角色的端点就会被踢出登录，误打断正常操作。

## 二、方案：后端拆分语义 + 前端集中拦截

### 2.1 后端 —— 按 Spring Security 标准语义拆开

**改动文件**：`fact-product/src/main/java/com/wms/config/SecurityConfig.java`

在 `securityFilterChain(...)` 的 `.sessionManagement()` 之后新增：

```java
.exceptionHandling()
    .authenticationEntryPoint(restAuthenticationEntryPoint())   // 未认证 → 401
    .accessDeniedHandler(restAccessDeniedHandler())             // 权限不足 → 403
.and();
```

两个 Bean（均在 `SecurityConfig` 内）：

| Bean | 触发条件 | 状态码 | 响应体 |
|---|---|---|---|
| `restAuthenticationEntryPoint()` | **未认证**：无 token / token 无效 / token 过期 | **401** | `{"code":401,"message":"登录状态已失效，请重新登录","reason":"AUTHENTICATION_REQUIRED","path":"..."}` |
| `restAccessDeniedHandler()` | **已认证但权限不足**（角色不匹配） | **403** | `{"code":403,"message":"没有访问权限，请使用具备相应角色的账号登录","reason":"ACCESS_DENIED","path":"..."}` |

**关键点**：
- `JwtRequestFilter` 本身**不写响应**，只是不写入 SecurityContext（保持匿名继续），
  最终由 Spring Security 的 `ExceptionTranslationFilter` 分派到上述处理器 —— 链路已实测确认。
- 响应体带 `reason` 字段，让前端能**确定性地**区分两种 403/401，不靠猜。
- `message` 字段让现有页面（普遍用 `e.response?.data?.message`）**无需改动**即可显示可读文案。

### 2.2 前端 —— 集中式判定与跳转

**新增文件**：`frontend/src/utils/auth-redirect.js`

集中承载：语义判定、上下文存取、安全回跳校验、跳转。

| 导出 | 作用 |
|---|---|
| `classifyForbidden(response)` | 判定 403 属于 `unauthenticated` 还是 `forbidden` |
| `shouldRedirectToLogin(response)` | 是否需要跳登录（401 恒为 true；403 走判定） |
| `saveLoginContext(path, query)` | 保存来源路由 + 原始请求参数到 `sessionStorage` |
| `takeLoginContext()` | 读取并**清除**上下文（用后即焚） |
| `peekLoginContext()` | 仅查看（登录页展示提示用） |
| `isSafeRedirect(path)` | 回跳白名单校验（防开放重定向） |
| `redirectToLogin(reason)` | 跳转登录页并带上原因 |
| `LOGIN_PATH` | 登录页路径常量（`'/login'`，与 `router/index.js` 一致） |

**判定优先级**（`classifyForbidden`）：

1. 响应体 `reason` 字段 —— 后端已显式区分，**最可靠**
2. 响应体 `message` 中文特征 —— 兜底
3. 本地 Token 是否仍有效 —— **后端未升级时的最终兜底**：
   - 本地无 token / 已过期 → 判定为**未登录** → 跳登录
   - 本地 token 仍有效 → 判定为**权限不足** → 只提示

> 第 3 条保证了即使后端是旧版本（两种情况都是 403），前端行为也不会错到
> 「把权限不足当成未登录」。

**改动文件**：`frontend/src/utils/request.js`

响应拦截器（**全站所有接口共用这一个 axios 实例，因此这一处覆盖全部接口**）：

```js
if (status === 401) {
  clearToken()
  saveLoginContext(currentPath(), requestParamsOf(error))
  redirectToLogin('登录状态已失效，请重新登录')
  return Promise.reject(error)
}

if (status === 403) {
  if (shouldRedirectToLogin(response)) {
    clearToken()
    saveLoginContext(currentPath(), requestParamsOf(error))
    redirectToLogin('登录状态已失效，请重新登录')
  } else {
    // 权限不足 → **不跳转**，仅透传错误 + 补可读原因
    error.authKind = 'forbidden'
    error.friendlyMessage = (response.data && response.data.message)
      || '没有访问权限，请使用具备相应角色的账号登录'
  }
}
```

### 2.3 登录页 —— 回跳与提示

**改动文件**：`frontend/src/views/auth/Login.vue`

| 项 | 改造前 | 改造后 |
|---|---|---|
| 失效提示 | 无 | 橙色 `.notice-msg`（区别于红色的密码错误 `.error-msg`） |
| 登录后去向 | 固定 `router.replace('/camera-status')` | 有上下文且通过安全校验 → `router.replace(ctx.path)`，否则回默认页 |
| 上下文读取 | — | `peekLoginContext()`（展示时不清除）、`takeLoginContext()`（登录成功时取用并清除） |

**开放重定向防护**：`isSafeRedirect()` 只放行站内绝对路径 + 白名单前缀，
拒绝协议相对地址（`//evil.com`）、外链（`https://...`）、以及登录/注册页自身。

## 三、上下文保留的内容

```json
{
  "path": "/system/config?tab=camera",   // 来源路由（含 query）
  "query": { "page": 1, "size": 999 },    // 原始请求参数（仅简单值）
  "at": 1787398402754                    // 时间戳（超 30 分钟视为陈旧，不再回跳）
}
```

- 存 `sessionStorage`（关闭标签页即失效，避免跨会话残留）
- **用后即焚**：登录成功时 `takeLoginContext()` 读取并删除
- 已有上下文时**不覆盖**（保留最早的来源）
- 请求参数只保留可序列化的简单值，避免把 `FormData` / 循环引用塞进 sessionStorage

## 五、验证方式与实测结果

### 5.1 后端三态语义（服务器实测）

```
=== A. 无 token 访问需认证端点 ===
  GET /api/cascade/all (无 token) -> 401
  body: {"code":401,"message":"登录状态已失效，请重新登录","reason":"AUTHENTICATION_REQUIRED","path":"/api/cascade/all"}

=== B. 过期/非法 token 访问 ===
  GET /api/cascade/all (伪造 token) -> 401
  body: {"code":401,...,"reason":"AUTHENTICATION_REQUIRED",...}

=== D. 关键对比：同一端点，admin vs 普通用户 ===
  admin      GET /api/user -> 200
  普通用户    GET /api/user -> 403
  无 token    GET /api/user -> 401
```

权限不足场景的响应体：

```json
{"code":403,"message":"没有访问权限，请使用具备相应角色的账号登录",
 "reason":"ACCESS_DENIED","path":"/api/user"}
```

> 验证用的临时普通用户（`ZZTEST_ROLE` / `ZZTEST_403UI`）**已全部删除，残留 0 条**，
> 库中现仅 `admin/role=1`。

`docs/验证脚本-403拦截器行为.cjs` —— 用 Puppeteer 的请求拦截，把前端 axios 真实收到的

  [通过] 401 时 token 被清除

## 六、遗留与后续建议

| # | 事项 | 说明 |
|---|---|---|
| 1 | **设备端点不受影响** | `/api/v1/**` 走 `cfg_camera_token` 体系，本就不参与 JWT 认证；实测无 token 调心跳仍返回 `code:500 缺少认证令牌`（HTTP 200），与本次改动无关 |
| 2 | **前端旧接口的 403 兜底** | 若后端某接口未经过 `SecurityConfig`（如自定义 `@ControllerAdvice` 抛 403），前端会走「本地 token 是否有效」兜底判定 —— 行为仍然正确 |
| 3 | **会话固定攻击面** | 回跳用 `sessionStorage` 存储，不含敏感信息；回跳目标经白名单校验，不会被用于跨站跳转 |
| 4 | **建议** | 若后续要在多标签页间同步登录态，可在 `auth.js` 里监听 `storage` 事件；本次未做，属于体验增强而非缺陷 |

## 七、踩坑记录（供后续维护参考）

| 坑 | 现象 | 结论 |
|---|---|---|
| Spring Security 默认未认证返回 403 | 与权限不足同形，无法在前端区分 | 必须显式配置 `AuthenticationEntryPoint` |
| `page.type(selector, text)` | 在 password 类型输入框上**静默失效**，值留空 | 用 `page.keyboard.type()` |
| `page.type()` 追加而非覆盖 | 登录页用户名框默认值 `'admin'` → 变成 `adminadmin` | 先 `Ctrl+A` + `Backspace` |
| `evaluate` 里用 value setter | Vue 的 v-model 在 input 事件里把值同步回去，赋了等于没赋 | 用真实键盘事件 |
| 已登录访问 `/login` | 被路由守卫重定向到 `/camera-status`，进不了登录页 | 需要进登录页时**先清 token** |
| 401 场景会清 token | 后续场景的 fetch 拿不到 token | 场景之间需重新登录 |
