## 三、优化方案（按优先级排序，附落地步骤）

### R1（P0，对应问题 1/1b）：图片上传接入令牌校验

**目标**：三设备端点同一鉴权口径。改动约 15 行 + 1 条回归。

1. `DefectImageServiceImpl.upload()` 入口处注入并调用 `CameraTokenVerifier.verify(token, deviceId)`（与 `CameraStatusServiceImpl` 完全同口径：`MISMATCH` 一律拒；`NOT_CONFIGURED` 按 `camera.token.strict` 决定；消息与错误码对齐 `AUTH_DEVICE_UNAUTHORIZED` / `TOKEN_NOT_CONFIGURED`）。
2. Controller 侧把取出的 token 传下去（现在取了就丢）。
3. 回归：`mvn test`；手动负向（错 token → 拒；无 token 且 strict=false → 放行 + WARN 日志）。
4. 同步改 `CODEBUDDY.md` 安全段——修复后该声明才为真；若暂不修代码，**必须先把声明改为如实描述**。
5. 更新 `相机设备接口协议.md` §8.3 缺口表（关闭缺口 1）。

### R2（P1，问题 2）：配置面 UI 缺口三选一

方案对比：

| 方案 | 内容 | 成本 | 适合 |
|---|---|---|---|
| A（推荐） | 恢复 3 个页面路由（`/system/brands`、`/system/defect-types` 直指现存视图 + 补映射页），纳入 ConfigView 或独立 | 中（1~2 天，含回归） | 交付期后可排期 |
| B | 不做 UI，改报错文案 + 文档指路：`PRODUCT_NOT_FOUND` 文案改为「请联系管理员通过 /api/v1/config/products 或 SQL 维护」；协议文档 §9 已写清手工路径 | 小（半小时） | **立即执行**，与 A 不冲突 |
| C | 只做 Excel 导入模板扩展 | 中 | 不推荐：映射表列多，Excel 易错 |

落地顺序：先 B（止血，改 `InspectionUploadServiceImpl.java:98` 文案），再 A（排期）。

### R3（P1，问题 3）：图片读取端点鉴权

1. 短期（运维侧）：确认现场 8091 不对外网暴露（防火墙/仅内网交换），写入部署检查项。
2. 中期（代码侧）：`/defect-images/file/**` 改为签名 URL（上传响应返回带 HMAC 的短期链接）或至少加 referer/网关鉴权；改动涉及前端 `<img>` 渲染链路，需排期。

### R4（P1，问题 4）：binlog 备份与过期

1. MySQL 侧设置 `binlog_expire_logs_seconds=604800`（7 天），纳入 `03_system_settings.sql` 或运维变更单。
2. `backup-database.sh` 增加 binlog 增量同步：每日全备后 `mysqlbinlog` 或直接拷贝未归档 binlog 至 `/var/backups/camera-detection/binlog/`（跨盘）。
3. `verify.sh` 加一项：binlog 目录非空且最新文件时间 < 25 h。
4. RPO 从 24 h 收敛到分钟级（配合恢复演练验证）。

### R5（P1，问题 5）：前端测试接入 CI

1. `frontend/package.json` 增加 `"test": "node --test tests/"`。
2. CI 前端构建 job 在 `npm ci` 后、build 前加一步 `npm test`（<5 s 成本）。
