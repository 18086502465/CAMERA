所有会变的值集中在下表。**现场参数只改表里标注的 4 个文件，其余不用动。**

## 3. 服务器操作

### 3.1 装 MySQL 8.0

- 字符集 `utf8mb4` / `utf8mb4_general_ci`
- **只绑 127.0.0.1**，不对外开放 3306
- 记下账号密码（填入 §1 表格）

### 3.2 建库（4 个脚本，按序）

```powershell
$SQL = 'D:/Program Files/CameraDetectionSystem/sql'      # ← 必须用正斜杠
$MY  = 'C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe'

& $MY -h 127.0.0.1 -P 3306 -u root -p -e "CREATE DATABASE IF NOT EXISTS ``wms-new`` DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"

& $MY -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 --database=wms-new --execute "source $SQL/01_init_schema_nodb.sql"
& $MY -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 --database=wms-new --execute "source $SQL/02_final_schema_p0.sql"
& $MY -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 --database=wms-new --execute "source $SQL/03_system_settings.sql"
& $MY -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 --database=wms-new --execute "source $SQL/04_align_entity_columns.sql"
```

**表数应为 34**（应用首次启动后运行时自建 4 张 `defect_image_*` + 4 张聚合表 → 38）。

> ⚠️ **建完库必须启动一次应用** —— 那 4 张表是应用启动时用
> `CREATE TABLE IF NOT EXISTS` 建的，不启动就没有，设备上报图片会因表不存在而报错。

> ⚠️ **五个 PowerShell 陷阱（均已实测踩坑并修正）**
>
> | 陷阱 | 现象 | 正确写法 |
> |---|---|---|
> | `-h127.0.0.1` | 报 `Unknown MySQL server host '127'`（PowerShell 按小数点拆参数） | `-h 127.0.0.1`（**中间有空格**） |
> | `mysql ... < file.sql` | 报「运算符是为将来使用而保留的」（PS 不支持 `<` 重定向） | `--execute "source 路径"` |
> | `Get-Content file \| mysql` | **中文全部变乱码**（`产品A` → `浜у搧A`），PS 管道会按 GBK 重编码 | 用 `--execute "source ..."`，让 mysql 自己读文件 |
>
> 另：**`source` 的路径必须用正斜杠**。反斜杠会被 mysql 当转义符，报 `Unknown command '\0'`。
>
> | 陷阱 | 现象 | 正确写法 |
> |---|---|---|
> | `-h127.0.0.1` | 报 `Unknown MySQL server host '127'`（PowerShell 按小数点拆参数） | `-h 127.0.0.1`（**中间有空格**） |
> | `mysql ... < file.sql` | 报「运算符是为将来使用而保留的」（PS 不支持 `<` 重定向） | `--execute "source 路径"` |
> | `Get-Content file \| mysql` | **中文全部变乱码**（PS 管道按 GBK 重编码） | 同上 |
> | `mysqldump ... > file.sql` | 产出 **UTF-16LE**，压缩与校验全过但**不是合法 SQL** | `--result-file=路径` |
> | `Start-Process` | 环境里有 `HTTPS_PROXY` 与 `https_proxy`（大小写不同）→ .NET 抛「已添加项…」 | 用 `&` + 原生重定向 |
>
> > 验证结论：用上面的写法建库后，`dim_product.product_name` = `产品A`、`dim_factory.factory_name` = `杭州工厂`，`cfg_camera_defect_mapping` 120 条，中文完好。

> ⚠️ `02` 会 DROP 并重建 21 张表，**只适用于空库**。已有数据的库升级见 §5。
> ⚠️ 交付包里的旧 `wms-new.sql` **不要用** —— 缺 15 张表，设备上报接口会 500。打包时已把它从 `sql\` 目录清掉（见 §2 步骤⑤）。
>
> ⚠️ `init-database.ps1` 的 `-SqlFile` 默认值仍指向已被移除的 `sql\wms-new.sql`，**该脚本在本方案下不适用**（它只支持导入单个 SQL 文件）。建库请直接用上面的 4 段命令。

### 4.1 一键自检（23 项）

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\verify-installation.ps1
```

失败会返回退出码 1。自检分组：

| 组 | 项数 | 内容 |
|---|---|---|
| 文件与运行时 | 5 | JRE / JAR / 配置 / 服务包装器 / **建库脚本四段齐全** |
| 服务与端口 | 4 | 服务存在 / 运行中 / 8091 监听 / 页面可访问 |
| **鉴权** | 4 | **匿名应被拒（401/403）** / 登录 / 带令牌可访问 / 设备端仍可用 |
| 运维三件套 | 4 | 备份 / 清理 / 巡检 / 计划任务注册脚本 |
| 计划任务 | 3 | 备份 / 清理 / 巡检是否已注册 |
| 备份产物 | 1 | 备份文件存在且 **sha256 可校验** |

> **鉴权那两项是 2026-10-28 新增的** —— 详见 §8。

### 4.2 功能基线（逐条核对）

```powershell
$B = 'http://localhost:8091'
```

| # | 命令 | 期望 |
|---|---|---|
| 1 | `curl -s -o /dev/null -w "%{http_code}" $B/` | `200` |
| 2 | `curl -s -o /dev/null -w "%{http_code}" $B/system/config` | `200`（SPA 深链可刷新） |
| 3 | `curl -s -X POST -H "Content-Type: application/json" -d '{"username":"admin","password":"见下"}' $B/api/auth/login` | `code:200` + token |
| 4 | `curl -s -X POST -H "Content-Type: application/json" -H "X-Device-Id: CAM-001" -H "Authorization: Bearer dev-token" -d '{"cameraName":"c","cameraCode":"CAM-001","cameraStatus":1}' $B/api/v1/camera/status/heartbeat` | `code:200` |
| 5 | 批量上报（同上加 `-H "X-Batch-Id: T1"`，body 用 `schemaVersion:"2.0"`、`sourceCode:"p0"`） | `code:200` `accepted:true` |
| 6 | 上条重发（同 `batchId`） | `code:200` `duplicate:true` |
| 7 | 上条把 `sourceCode` 改成 `P0_INNER_GLUE_SMALL` | `code:422` `UNMAPPED` |
| 8 | `curl -s -H "Authorization: Bearer <token>" $B/api/stats/dashboard-overview` | `code:200`（**这条验证 `04` 补列是否生效**；鉴权已收紧，**不带 token 会 403**） |
| 9 | `curl -s $B/api/stats/dashboard-overview`（**不带 token**） | `403`（**这条验证鉴权确实生效**） |

> **第 3 条的"见下"**：
> - **全新建库**（用 §3.2 的 4 段脚本）→ 种子账号是 `admin` / **`123456`**
> - **迁移已有库** → 沿用原库口令（本机 `wms-new` 库为 `admin` / `admin`）
>
> 两种口径的差异来源：`04_align_entity_columns.sql` 原先直接 `DROP COLUMN password`，
> 把 `01` 种子里的 BCrypt 哈希一起丢掉了，导致全新库登录永远提示"用户名或密码错误"。
> **已修复**：该脚本现在先把 `password` 的值搬到 `password_hash` 再删列，
> 同时 `01` 里的种子哈希也已换成实测 `matches("123456")` 为真的有效值。
> 若现场库是修复前建的，手工执行一次即可：
> ```sql
> ALTER TABLE `sys_user` ADD COLUMN `password_hash` VARCHAR(255) NULL AFTER `username`;
> UPDATE `sys_user` SET `password_hash` = `password` WHERE `password` IS NOT NULL;
> ALTER TABLE `sys_user` DROP COLUMN `password`;
> ```
> 上线前一律先改口令（Ubuntu 版有 `reset-password.sh`，Windows 版需手工生成 BCrypt 哈希）。

### 4.3 设备侧 4 项确认

1. `cfg_camera_token` 里有该相机的 token
2. `dim_camera` 里有该相机记录（`camera_code`/`device_id`/所属产线工位）
3. `cfg_camera_defect_mapping` 里配了「相机 + 来源编码 → 缺陷类型」
4. 相机上报的 `sourceCode` 与映射表 `source_code` **完全一致（大小写敏感）** —— 有效值形如 `p0`、`p1`

## 5. 升级 / 回滚

```powershell
# 变量（与 §3.2 保持一致）
$MY  = 'C:/Program Files/MySQL/MySQL Server 8.0/bin/mysql.exe'
$MYD = 'C:/Program Files/MySQL/MySQL Server 8.0/bin/mysqldump.exe'
New-Item -ItemType Directory -Force -Path D:/backup | Out-Null

# 备份：必须用 --result-file，让 mysqldump 自己写文件
# （直接 `>` 在 PS 5.1 下生成 UTF-16LE；经管道则中文乱码，备份都不可用）
& $MYD -h 127.0.0.1 -u root -p --single-transaction --routines --hex-blob `
  --result-file="D:/backup/wms-new_$(Get-Date -Format yyyyMMdd_HHmmss).sql" wms-new

powershell -ExecutionPolicy Bypass -File .\scripts\stop-service.ps1
Copy-Item D:\新包\time-bucket-demo.jar .\app\ -Force
# 库结构有变更时：先在测试库演练增量 SQL，绝不跑全量 02
powershell -ExecutionPolicy Bypass -File .\scripts\start-service.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\verify-installation.ps1

# 回滚
powershell -ExecutionPolicy Bypass -File .\scripts\stop-service.ps1
Copy-Item D:\backup\time-bucket-demo.jar.bak .\app\time-bucket-demo.jar -Force
& $MY -h 127.0.0.1 -P 3306 -u root -p --default-character-set=utf8mb4 --database=wms-new `
  --execute "source D:/backup/wms-new_<时间戳>.sql"
powershell -ExecutionPolicy Bypass -File .\scripts\start-service.ps1

# 卸载
powershell -ExecutionPolicy Bypass -File .\scripts\uninstall-service.ps1
```

## 7. 改造指引：怎么改成自己的样子

按「需求 → 改哪里 → 验证」三步走。**每项改动都有明确的验证命令，改完立即可验。**

| 想改成什么 | 改哪里 | 怎么验证 |
|---|---|---|
| **换端口** | `installer/templates/application.yml` 的 `server.port`<br>+ `installer/scripts/verify-installation.ps1` 的 `$BaseUrl` 和端口检查<br>+ `installer/camera-detection-system.iss` 的快捷方式 URL | 改完装包后跑 `verify-installation.ps1`，应显示「TCP <新端口> 监听 通过」 |
| **换数据库名** | `installer/templates/application.yml` 的 `spring.datasource.url`<br>+ `installer/scripts/init-database.ps1` 的 `$Database` 默认值 | 建库时 `CREATE DATABASE` 同步改；`SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='<新库名>'` 应为 34 |
| **换数据库密码** | `installer/templates/application.yml` 的 `spring.datasource.password`<br>+ `installer/scripts/init-database.ps1` 的 `$Password` 默认值 | 装完包后 `mysql -h 127.0.0.1 -u root -p<新密码> -e "SELECT 1"`，再登录接口应返回 `code:200` |
| **换安装目录** | `installer/camera-detection-system.iss` 的 `DefaultDirName` | 装包时确认落盘路径；`verify-installation.ps1` 会检查 jar/config/jre 是否在 `{app}` 下 |
| **换工作目录**（数据盘） | 不用改代码。装包时在向导里选，或 `install-service.ps1 -WorkDir 'D:\xxx'` | 检查 `D:\xxx\logs\` 与 `D:\xxx\data\uploads\` 是否生成 |
| **换服务名** | `installer/service-wrapper/CameraDetectionService.cs` 的 `ServiceName`<br>+ `installer/scripts/` 下 5 个 ps1 的 `$serviceName`<br>+ `.iss` 的 `UninstallDisplayIcon` | `Get-Service <新名>` 应存在；`service-status.ps1` 应正常输出 |

## 9. 运维三件套（2026-10-28 新增）

> 改造前 Windows 版**完全没有备份**，磁盘也没有任何告警。这三件套与 Linux 版行为对齐。

### 9.1 数据库全量备份

```powershell
# 手工跑一次
powershell -ExecutionPolicy Bypass -File .\scripts\backup-database.ps1 `
  -DbPassword '你的口令' -BackupDir 'D:\CameraDetection\backup\db'
```

- `--single-transaction` —— 不锁表，业务无感知
- 备份前检查磁盘水位 —— 与数据同盘时，写满就不再写入
- gzip 压缩 + `.sha256` 校验文件
- 保留 14 天，过期自动删除
- **口令走 `MYSQL_PWD` 环境变量，不出现在进程命令行**

### 9.2 缺陷图片清理

```powershell
# 预演
powershell -ExecutionPolicy Bypass -File .\scripts\cleanup-defect-images.ps1 -DbPassword '你的口令' -DryRun
# 实际执行
powershell -ExecutionPolicy Bypass -File .\scripts\cleanup-defect-images.ps1 -DbPassword '你的口令'
# 以库记录为准（文件很新但库判定过期时用）
… -PurgeDb
```

> ⚠️ **清理顺序必须是「先删库记录、再删磁盘文件」**：
> 反过来会产生孤儿记录（记录在、文件没了）→ 前端显示破图且记录永不复收。
> 脚本在**连不上数据库时会拒绝删文件** —— 这个保护是故意的。

### 9.3 磁盘水位巡检

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\check-disk-usage.ps1 -Drives 'C D' -Threshold 85
```

超过阈值写本地告警文件 + **Windows 事件日志**（源 `CameraDetection`，EventID 3001），退出码 1。

### 9.4 注册计划任务

```powershell
# 1) 写口令文件（只含一行）
'C:\Program Files\CameraDetectionSystem\config\backup.conf' |
  ForEach-Object { "MYSQL_PASSWORD=你的口令" | Set-Content -LiteralPath $_ -Encoding UTF8 }

# 2) 以管理员身份注册
powershell -ExecutionPolicy Bypass -File .\scripts\register-scheduled-tasks.ps1

# 3) 查看 / 试跑
Get-ScheduledTask -TaskName 'CameraDetection*' | Format-Table TaskName,State
Start-ScheduledTask -TaskName 'CameraDetection-Backup'
```

| 任务名 | 触发 | 说明 |
|---|---|---|
| `CameraDetection-Backup` | 每天 **01:00** | 数据库全量备份 |
| `CameraDetection-CleanupImages` | 每天 **03:30** | 图片与元数据清理（错开应用内 02:00） |
| `CameraDetection-DiskUsage` | **每 30 分钟** | 磁盘水位巡检 |

> 备份选 01:00 的理由：**早于**应用内 02:00 的清理 —— 备份的是**清理前的完整状态**。
