产线统计：功能说明与配置手册

本手册逐项说明「产线统计」页面每个功能的作用、操作步骤与触发条件，明确能力边界， 并完整列举可通过配置产出的统计数据项（配置方式 · 参数含义 · 适用前提 · 限制条件）， 附页面效果示意与管理层报表口径。

适用版本：v3（2026-11-06 改造后） 数据通道：缺陷图片事实表（现场）/ 质量聚合表（兜底） 页面路径：统计 → 产线统计

00阅读指引

按角色选最短路径，不必从头读。

管理层 / 厂长
关心「车间今天怎么样、问题在哪」。先读 1、3，再看 6 的报表口径表。
→ 页面定位 · → 管理层报表项
工艺 / 质量工程师
要定位「哪类缺陷、哪个工位、哪台相机」。读 2.4 与 4 的统计项配置。
→ 图表组件 · → 统计项配置
实施 / 运维
页面数字为 0 或与预期不符时，先查 3 的能力边界与 7 的排查清单。
→ 能力边界 · → 快速上手
一句话结论 这是一个「缺陷检出侧」的统计页 —— 它统计的是「发现多少缺陷、集中在哪」， 而不是「生产了多少件、良率多少」。现场设备只上报缺陷图、不上报良品图， 因此良率在本页恒为「不可计算」，这是设计行为，不是故障。

01页面定位与数据流

理解数据从哪来，是判断「数字对不对」的前提。

页面把两条上报通道的数据统一成一个响应结构，按「当前时间窗内有没有缺陷图片」自动二选一， 而不是把两边相加。这一点决定了所有指标的口径：

判定结果数据来自良率时间粒度典型场景
DEFECT_IMAGE defect_image_file / _box 不可计算（null） 趋势固定 1 小时桶 现场正常生产，近 31 天内
AGGREGATION agg_quality_* / agg_defect_type_* 可算（OK/总数） 30 分钟 或 天 查询 31 天以前，或从未接入图片通道
易错点：两个通道的「检测总数」不是同一个东西 图片通道下它是缺陷图片张数（每张图 = 一次检测事件）；聚合通道下它是上报的检测件数。 两个数放在一起比较没有意义，切换数据源时请不要横向对比。

2.2 指标卡（KPI）

指标卡会随数据源换一套形态，不是同一套卡换数字：

指标卡区筛选条下方 只读·自动刷新
作用
一眼看规模与风险：多少检测、多少缺陷、高危占多少。

新增图表的两种入口

2.6 日聚合运维（仅聚合通道需要）

当查询范围 ≥ 3 天且落到聚合表时，数据的「新鲜度」由后台任务保证。这一区域是给运维用的， 业务用户平时不用碰。

  • 自动刷新：每 5 分钟重算近 3 天窗口（不写任务表，只在应用日志留痕）。
  • 夜间定时：默认 02:00、回溯 7 天，可改时刻与回溯天数（1–365）。
  • 手动执行：指定起止日期立即补算，默认近 7 天。
  • 任务列表：分页查看历史任务，失败项可「重试」（按原区间重提）。
  • 状态标签：显示最近一次任务的成功/失败与耗时。
现场图片通道下这块基本不产生新数据 日聚合表的数据源是 30 分钟聚合表，而 30 分钟表只由旧接口 batch-upload 写入。 现场只跑图片通道 → 聚合表没有新数据 → 近 3 天窗口的刷新是空转。这不影响页面显示（页面走图片源）。

限制：7 格固定，不能增删；「受影响工位/相机」分母只含有相机关联的图，未建档设备的图不计入。

② 核心质量指标（quality）

作用：传统的四宫格质量卡（检测总数 / OK / NG / 良率）。

配置：类型 KPI → 指标「核心质量指标」→ 尺寸 12×1。

适用前提：只有聚合通道才有意义。图片通道下 OK 恒为 0、良率是 null， 卡片会显示 0.00%（这一形态不判断「是否可算」）。

限制：现场使用请改用「工厂总览」，它会把良率显示成「—」而不是 0%。

③ 30 分钟质量趋势（trend）

作用：看产量与异常的时段分布，找「什么时候开始变差」。

配置：类型 LINE → 指标「30 分钟质量趋势」→ 维度「时间」→ 12×3。

参数含义：X 轴为时间桶；Y 轴左为数量，右为良率（仅有良率数据时出现）。

前提与限制：

  • 聚合通道：粒度随跨度变（30 分钟 / 天）。
  • 图片通道：永远按 1 小时分组，即使页面标签写着「30 分钟」。
  • 图片通道下不画良率线，也只用单 Y 轴 —— 这是刻意的，避免画出 0% 假曲线。

④ 缺陷发生趋势（defectTrend）

作用：只关注缺陷侧的时间分布（柱 = 缺陷数，线 = 异常数），是图片通道下最有用的趋势图。

配置：类型 LINE → 指标「缺陷发生趋势」→ 维度「时间」→ 12×3。

前提：无；两通道均可用。限制：颗粒度同上（图片源 1 小时）。

⑤ 缺陷类型帕累托（defectPareto）

作用：按缺陷数降序 + 累计占比曲线，一眼看出「前几类缺陷贡献了 80% 的问题」。

配置：类型 BAR 或 PARETO → 指标「缺陷类型帕累托」→ 维度「缺陷类型」→ 8×3 或 12×3。

参数含义：左轴缺陷数、右轴累计占比（上限 100%）、红色虚线为 80% 基准线；累计占比的分母是前 20 行缺陷数之和，不是全量。

前提：缺陷类型名来自上报文本（图片通道）或缺陷字典（聚合通道）。

限制：只显示前 12 类；分类超过 6 个时 X 轴标签自动倾斜 24°。

⑥ 缺陷类型排行（defectRanking）

作用：横向条形 Top 榜，适合贴在周会材料里。

配置：类型 RANK → 指标「缺陷类型排行」→ 维度「缺陷类型」→ 6×3。

限制：取数 Top 20，图表只画前 12，无 TopN 配置项；导出 Excel 可得 20 行。

⑦ 缺陷严重度构成（severityDistribution）

作用：判断质量风险等级 —— 高危占比升高比总量升高更值得报警。

配置：类型 SEVERITY → 指标「缺陷严重度构成」→ 维度「严重度」→ 4×3。

参数含义：环形图，四段为 HIGH / MEDIUM / LOW / UNKNOWN。

限制：图例显示英文原值（HIGH/MEDIUM/LOW），与筛选器里的中文（高危/中等/轻微）不一致，属已知表现。

⑧ 缺陷严重度堆叠（stackDefectBySeverity）

作用：把「哪类缺陷」和「多严重」放在一张图上 —— X 轴缺陷类型，每根柱按严重度分段堆叠。

配置：类型 STACK_BAR → 指标「缺陷严重度堆叠」→ 维度「缺陷类型 + 严重度」→ 12×3。

前提：缺陷框上必须有 severity 值，否则全部落到 UNKNOWN。

限制：取前 12 个缺陷类型；堆叠由前端按「类型 + 严重度」二次聚合。

⑨ 责任工位定位（stationRanking）· ⑩ 责任相机定位（cameraRanking）

作用：把缺陷归因到具体工位/设备，是「找责任点」最直接的两张图。

配置：类型 BAR → 指标「责任工位定位」/「责任相机定位」→ 维度「工位」/「相机」→ 6×3，常并排放。

参数含义：按 NG 数降序；副排序为检测总数。

前提：相机必须在 dim_camera 建档。图片表存的是相机编号， 关联不上维度表的图片仍计入总量，但不会出现在这两张图里。

限制：取数 Top 20，展示前 12。

⑪ 产品缺陷透视表（defectPivot）

作用：产品 × 缺陷类型的交叉矩阵，看「哪个产品的问题集中在哪类缺陷」。

配置：类型 PIVOT → 指标「产品缺陷透视表」→ 维度「产品 + 缺陷类型」→ 12×4。

前提：必须走聚合通道（图片表没有产品列）。

限制：

  • 聚合通道：列数无后端上限，前端最多渲染 30 列。
  • 图片通道：退化成「按缺陷类型分组」，所有行的缺陷 ID 都是 0， 前端按 ID 去重时会塌缩成一列 —— 透视表在图片通道下实际不可用。

⑫ 映射异常明细（mappingExceptions）

作用：列出上报的缺陷编码在字典里找不到的样本，是「数据对不上」时的第一排查入口。

配置：类型不限（表格渲染）→ 指标「映射异常明细」→ 12×3。

限制：只显示最近 10 条未处理（status=OPEN）的记录；处理入口不在本页。

05效果图展示区

按使用顺序排列：进入页面 → 切时间 → 看指标 → 加图 → 配置 → 大屏 → 导出。

6.1 给汇报材料的三点建议

  1. 不要把「检测总数」写成「产量」。现场是缺陷图张数，不是生产件数。 如果汇报需要产量，只能从 MES 取，不要用这个数替代。
  2. 良率不要留空，要写「未接入」并说明原因。留空会被理解为 0% 或忘记填； 写「设备仅上报缺陷图，无良品样本」是准确且可解释的。
  3. 趋势图的横轴单位要标注清楚。图片通道是 1 小时、聚合通道是 30 分钟或天， 同一张图在不同时间范围下横轴间隔不同，汇报时注明可避免「为什么昨天是 24 个点、上周是 7 个点」的疑问。

07快速上手

三个高频场景，按步骤做即可。

7.1 厂长：5 分钟搭一个汇报看板

  1. 顶部「新建模板」→ 名称填「厂长日报」→ 范围选「工厂模板」→ 保存。
  2. 点「新增图表」→ 在弹窗里点预设「工厂总览」→ 保存（自动 12×2）。
  3. 再新增 → 预设「缺陷帕累托」→ 保存。
  4. 再新增 → 预设「严重度构成」→ 保存。
  5. 再新增 → 预设「工位异常」→ 保存，拖动到帕累托右侧。
  6. 回到顶部，用时间档位「近 7 天」核对数字；确认无误后点「看板大屏」演示。

7.2 工艺工程师：定位「哪个工位哪类缺陷」

  1. 时间先选「今天」，缩小范围。
  2. 看「责任工位定位」找最高的那根柱 → 记住工位名。
  3. 用顶部相机下拉（或产线全局筛选）收敛到该工位。
  4. 看「缺陷类型帕累托」，读前 2–3 类缺陷及累计占比。
  5. 看「缺陷严重度堆叠」，确认这些缺陷是高危还是轻微。
  6. 需要明细时，把该图导出 Excel，拿 Top 20 全量清单。

7.3 运维：页面数字是 0 / 对不上，按这个顺序查

  1. 先看数据源标签：筛选条右侧写「30 分钟聚合」还是「日聚合」，指标卡是 5 张还是 6 张 —— 5 张 = 图片通道，说明图确实进来了。
  2. 确认时间窗内真的有图：换「今天」档位，若仍为 0，去数据库查 defect_image_file 当天行数与 capture_time 范围。
  3. 确认相机已建档：图片表的相机字段存的是相机编号，若 dim_camera 里没有该编号，图片会计入总量但不出现在工位/相机排行里。
  4. 确认筛选没被误用：图片通道下，选中「产品 / 班次 / 缺陷类型」不会生效， 但如果同时选了产线而产线无数据，结果就会是 0。
  5. 确认是否超过 31 天：超出热表范围，页面会自动切聚合表；聚合表没数据就是全 0。
  6. 确认测试相机：测试设备的数据会算进统计，最多 1 小时后被清理任务删除。
正常状态的自检基线（现场 2 台真实相机） 指标卡 5 张、良品样本显示「未接入」、趋势图无良率线、帕累托前 3 类占比合计约 70–80%、 工位排行 2 行左右、相机排行 2 行。若与这个形态差异很大，先按上面 6 步排查。
