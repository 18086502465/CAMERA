## 2. 构建过程

### 2.1 清理旧产物

首次构建发现 `frontend/dist/assets` 残留 **133** 个 chunk（旧构建哈希文件未清除），
而 JAR 内 static 目录只有 102 个 —— 说明历史构建一直采用增量覆盖，
**旧 chunk 会残留在 JAR 里**，既增大体积，也存在被浏览器误引用的风险。

处理：先删除 `frontend/dist/assets` 与 `fact-product/src/main/resources/static/assets`
两个目录，再重新构建。重建后产物 **49** 个文件，前后一致。

> 建议：后续 `npm run build` 若因沙箱安全删除超时无法清空目录，
> 应先手工删除 `dist/assets` 再执行 `npx vite build --emptyOutDir false`。

### 3.3 踩坑记录

| 坑 | 现象 | 处理 |
|---|---|---|
| `sudo -S` + heredoc | `bash: line 1: nset: command not found` | 改为**独立脚本文件**上传后 `sudo -S bash /tmp/xxx.sh` |
| 登录接口路径写错 | `/api/v1/auth/login` → 403 | 正确路径是 **`/api/auth/login`**（前端 baseURL `/api`，登录接口不带 `/v1`） |
| bash 反引号 | 库名写成 `` `wms-new` `` 被当命令替换 | 必须用**单引号** `'wms-new'` |
| 普通用户无写权限 | `touch: Permission denied` | `/opt/.../app` 属 `cdsys`，需 `sudo` |

## 5. 遗留事项（未在本次处理）

1. **临平二期两台相机仍无缺陷映射、无设备令牌** — `cfg_camera_defect_mapping` 与 `cfg_camera_token` 中无对应记录。
   当前令牌查询为空时直接放行，意味着**任意 Token 都可上报**；投产前必须配置独立令牌。
2. **`sourceCode=p0` 尚无映射关系** — 设备端上报 `p0` 会返回 422 `UNMAPPED`。
3. **异机备份、设备端 JPEG 输出** — 已按决定本期不做。
4. **Windows 版本已停止维护** — 后续不再同步修改 `installer/scripts/*.ps1` 与 `dist-release/CameraDetectionSystem/`。

## 6. 回滚方式

```bash
# 服务器上执行
echo "Pass@1234" | sudo -S bash -c '
  systemctl stop camera-detection
  cp -a /opt/camera-detection-system/app/time-bucket-demo.jar.bak-20261102_200154 \
        /opt/camera-detection-system/app/time-bucket-demo.jar
  chown cdsys:cdsys /opt/camera-detection-system/app/time-bucket-demo.jar
  systemctl reset-failed camera-detection
  systemctl start camera-detection
'
```

回滚后同样需核验：`systemctl is-active` + `curl -o /dev/null -w "%{http_code}" http://127.0.0.1:8091/`
