# 服务器授权（License）设计

> 落地日期：2026-11-12。对应代码：`com.wms.shared.license.*` + `com.wms.system.app.LicenseService`。
> 签发工具：`installer/linux/scripts/gen_license.py`。本文是**协议与策略的唯一说明**，改字段/改策略先改这里。

---

## 一、要解决什么，不解决什么

| 要解决 | 不解决 |
|---|---|
| 授权到期后可发现、可提醒、可到期停服（策略可配） | **不防逆向**。密钥在 jar 里，反编译就能自行签发 |
| 授权换机器不能直接用（机器绑定） | 不防"把整个 jar + 授权拷到同型号机器"（除非绑定机器码） |
| 相机数量可按合同限制 | 不做在线激活、不做联网校验、不做心跳回传厂商 |
| 客户能看到自己的到期日，减少扯皮 | 不做功能级灰度（`features` 字段预留但当前不参与判定） |

**部署环境前提**：现场内网、无外网、无授权服务器。所以一切离线：签发机生成文件 → 拷到服务器 → 上传生效。

---

## 二、文件格式

单行 ASCII 文本，扩展名 `.lic`：

```
base64url(payloadJson) + "." + base64url(hmacSha256(payloadJson, secret))
```

- **载荷明文可读**（base64 解码即 JSON）：客户能自行核对到期日，减少争议。
- **签名不可伪**：改任何一个字节，验签即失败。
- 用 HMAC-SHA256 + URL-safe Base64（无 padding），JDK 自带，不引第三方库。
- 换行会被忽略，方便邮件/微信传输时折行。

---

## 三、载荷字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `version` | int | 是 | 当前固定 `1`。改结构必须升版本，否则老文件被判无效 |
| `licenseId` | string | 否 | 授权单号，如 `LIC-20261112-153000`，用于对账与告警文案 |
| `customer` | string | 是 | 客户名称，显示在授权页 |
| `issuedAt` | string | 否 | 签发日 `yyyy-MM-dd`，**同时作为生效日**：早于它会判 `NOT_YET` |
| `expireAt` | string | 是 | 到期日 `yyyy-MM-dd`，**含当天**，次日 00:00 起算过期 |
| `maxCameras` | int | 是 | 相机数上限；`-1` = 不限；`0` 与 `< -1` 属非法，直接判 `INVALID` |
| `features` | string[] | 否 | 预留，仅展示，当前不参与判定 |
| `machineCode` | string | 否 | 绑定机器码；`*` = 不绑定（默认） |

## 四、机器指纹

采集顺序（取到第一个有效即停）：

| 顺序 | 来源 | 特点 |
|---|---|---|
| 1 | `/sys/class/dmi/id/product_uuid` | 最稳，重装系统不变；部分内核需 root，服务以 `cdsys` 运行可能读不到 |
| 2 | `/etc/machine-id` | 644 可读，重装系统会变 |
| 3 | `/var/lib/dbus/machine-id` | 老发行版才有 |
| 4 | `/sys/class/dmi/id/board_serial` | 虚拟机常返回 `Not Specified`（判为无效） |

对外只暴露 `sha256("wms-cds-machine-v1|" + 原始值)` 的 **前 16 位大写十六进制**：

- 不可逆推硬件序列号（不泄露设备隐私）；
- 加盐避免与其他系统的短码撞库；
- 四个来源全部不可读时返回 `null`，此时**跳过**机器绑定校验并打 WARN —— 容器/精简系统上读不到是常态，不该让授权把系统卡死。

> 排障开关：`license.enforce-machine=false` 可整体关闭绑定校验（虚拟化批量部署时用）。

## 五、状态机

```
              enabled=false ──────────────► DISABLED（全放行）
              文件不存在 ─────────────────► MISSING
              验签/字段非法 ───────────────► INVALID
              机器码不符 ─────────────────► MACHINE_MISMATCH
              today < issuedAt ───────────► NOT_YET
              today > expireAt ───────────► EXPIRED
              expireAt - today <= warn-days ─► EXPIRING
              其他 ────────────────────────► VALID
```

每次 `getState()` 都按**当天**重算剩余天数，跨天无需重启；文件 mtime 变化会在 30 秒内自动重载。

---

## 六、三种过期策略

配置项 `license.expired-mode`：

| 模式 | 过期/无效时行为 | 适用场景 |
|---|---|---|
| `warn`（默认） | **只日志告警，永不阻断** | 首次交付、策略未定的现场 |
| `readonly` | 过宽限期后拒绝**设备写入**（上传/心跳/batch），管理端照常 | 已确认授权流程后的正式运行 |
| `block` | 在 readonly 基础上再拒绝业务查询，仅留登录与授权页 | 严格商务约束（慎用） |

**宽限期** `license.grace-days`（默认 7 天）：到期后仍给客户缓冲，宽限期内即使 `readonly` 也不拦。

**为什么默认 `warn`**：这是产线系统，一次误判就是停线。授权机制先做到"可见、可告警、可续期"，强制必须由运维在授权装好后显式开启。

> ⚠ 交付提醒：默认 `warn` 意味着**不装授权也能全功能跑**。若交付要求必须授权才能用，部署后把 `expired-mode` 改为 `readonly`。

## 七、拦截点

| 位置 | 触发条件 | 行为 |
|---|---|---|
| `LicenseGuardInterceptor`（设备写） | `writeBlocked=true` 且 POST 三个设备端点 | 返回 HTTP 200 + `code=503` + `errorCode=LICENSE_EXPIRED` |
| `LicenseGuardInterceptor`（全站） | `isAccessBlocked()`（仅 block 模式） | 除 `/api/license/**`、`/api/auth/login`、`/api/auth/me`、`/api/alerts/active` 外全部拒绝 |
| `CameraDashboardController.create` | 新增相机时 | `dim_camera` 有效行数 ≥ `maxCameras` → 拒绝，提示"已达授权上限" |
| `LicenseCheckTask` | 每小时 05 分 | 状态变化时打日志（抑制重复） |

**为什么用 HTTP 200 + body code=503**：设备固件按 body 的 `code/message` 判结果，改 HTTP 状态码会被当成网络故障无限重试。管理端 axios 同样按 body 处理。

**配额只在新增时校验**：不会因为授权到期就把已有相机数据清掉，也不会影响历史查询。

## 八、签发

在**你自己的机器**上（离线）：

```bash
# 1) 在服务器上取机器码（二选一）
python3 installer/linux/scripts/gen_license.py fingerprint
curl -s http://127.0.0.1:8091/api/license/machine-code -H "Authorization: Bearer <jwt>"

# 2) 签发
python3 installer/linux/scripts/gen_license.py issue \
    --customer "杭州临平一期" \
    --expire 2027-11-12 \
    --max-cameras 30 \
    --machine 3F9A1C77B2D4E580 \
    -o camera-detection.lic

# 3) 本地先验一遍（不装到服务器就能确认签对了）
python3 installer/linux/scripts/gen_license.py inspect camera-detection.lic
```

- `--machine '*'` 不绑定机器；`--max-cameras -1` 不限相机数。
- 签发不需要联网、不需要访问数据库。
- **密钥**：默认由 `LicenseSigner.SECRET_PART1/SECRET_PART2` 推导。若现场用 `LICENSE_SECRET` 覆盖，签发时必须带同一个 `--secret`，否则签出来的文件服务器一律验签失败。

## 九、安装与更新

文件位置：`${app.home}/data/license/license.lic`（现场为 `/main/app/data/license/license.lic`）。

**为什么放 data 盘而不是 `/etc`**：应用以 `cdsys` 运行，`/etc` 下的 640 root 文件它写不进去，"上传新授权"会永远失败。data 目录属 `cdsys`，且已在 systemd `ReadWritePaths` 内。

两种安装方式：

1. **页面上传**（推荐，管理员）：`/system/license` → 选择 `.lic` → 上传并生效。
   流程是「内存验签 → 校验机器绑定 → 备份旧文件 → 原子替换」，**验签失败一个字节都不动**。
2. **手工投放**（无浏览器/批量）：

```bash
sudo install -d -o cdsys -g cdsys -m 0755 /main/app/data/license
sudo install -o cdsys -g cdsys -m 0644 camera-detection.lic /main/app/data/license/license.lic
sudo systemctl restart camera-detection     # 或调 POST /api/license/reload 免重启
```

## 十、安全边界（如实说明）

| 威胁 | 是否挡住 | 说明 |
|---|---|---|
| 改到期日 / 改相机数 | ✅ | 签名覆盖整个载荷 |
| 把授权拷到别的机器 | ✅（绑了机器码时） | 指纹不符 → MACHINE_MISMATCH |
| 从 jar 里提取密钥自行签发 | ❌ | 对称密钥的固有缺陷 |
| 反编译去掉校验代码 | ❌ | 需代码混淆/VMP，成本远高于收益 |

**升级路径**：把 `LicenseSigner` 换成 ECDSA（jar 内只放公钥，私钥仅存签发机），上层 `LicenseService` 无需改动。当前不做，是因为对称密钥"够用且实现最不容易错"——一个能正确验签的 HMAC 远好过一个写错 padding 的 RSA。

## 十一、可观测

- 启动时打一条：`授权状态: VALID —— 授权正常，剩余 414 天（模式 warn，文件 …）`
- 每小时巡检，**仅状态变化**时记录（避免刷屏）
- 授权页 `/system/license`：状态横幅、剩余天数、机器码（可复制）、当前策略、会否阻断
- 接口：`GET /api/license`（登录用户）、`GET /api/license/machine-code`、`POST /api/license/upload|reload`（ADMIN）

## 十二、配置项

| key | 默认 | 说明 |
|---|---|---|
| `license.enabled` | `true` | 总开关；`false` 时状态为 DISABLED，全部放行 |
| `license.secret` | 空（用内置） | 建议用 `LICENSE_SECRET` 环境变量注入，**换密钥后旧授权全部失效** |
| `license.file` | `${app.home}/data/license/license.lic` | 授权文件路径 |
| `license.expired-mode` | `warn` | `warn` / `readonly` / `block` |
| `license.grace-days` | `7` | 过期后宽限天数 |
| `license.warn-days` | `30` | 剩余天数 ≤ 该值进入 EXPIRING |
| `license.enforce-machine` | `true` | 是否校验机器绑定 |

配置分层与覆盖顺序见 [`配置项清单.md`](配置项清单.md)。

## 十三、测试覆盖

`LicenseSignerTest`（9 项）+ `LicenseServiceTest`（12 项）：

- **跨语言互通**：用 `gen_license.py` 真实签发的文件固化为 golden vector，Java 必须能解析 —— 任一端改算法立刻红灯；
- 篡改签名段 / 篡改载荷 / 错误密钥 → 必须拒绝；
- 相机上限 `0` 判非法、版本 `2` 判不支持；
- 未安装 / 有效 / 即将到期 / 已过期 / 宽限期边界；
- `warn` 不拦、`readonly` 超宽限拦设备写、`block` 封全站；
- 机器码不符拦截、开关关闭后放行；
- 配额：未达上限放行、达到/超过拒绝、`-1` 不限、授权不可用时不误报。
