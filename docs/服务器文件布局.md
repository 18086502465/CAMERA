# 服务器文件与目录布局

> 最后校准：2026-11-10（新机 Ubuntu 24.04 实机部署后逐项核对）。
> 本文所有路径均取自脚本实际写入点：`install.sh` / `deploy.sh` / `backup-database.sh` /
> `cleanup-*.sh` / `installer/linux/systemd/*`，不是设计意图。
> 路径改动前必读 **§十一 联动清单** —— 改一个路径要同步 5 处，漏一处就是静默失效。

## 二、程序目录 `/opt/camera-detection-system`

| 路径 | 权限/属主 | 写入方 | 说明 |
|---|---|---|---|
| `app/time-bucket-demo.jar` | 0644 cdsys | `install.sh` | Spring Boot 可执行 JAR；前端产物内嵌在 `BOOT-INF/classes/static`，**不存在独立的 static 目录** |
| `config/application.yml` | 0640 cdsys | `install.sh` | 外部配置，按 key 合并覆盖 JAR 内配置；查"实际生效值"要先看它 |
| `sql/` | 0644 | `install.sh` | 6 段建库脚本，`init-database.sh` 按 01→05 导入，06 为索引调优（幂等，可选） |
| `scripts/` | 0755 | `install.sh` | `run.sh` 是 systemd 唯一入口；`verify.sh` 是验收；`deploy.sh` 是新机一键部署 |
| `docs/` | 0644 | `install.sh` | 随包手册，便于现场离线查阅 |

**覆盖策略（`install.sh` 第 3 节）**：JAR 每次覆盖；`config/application.yml` **只在首次安装时复制**，
之后保留现场改动；`sql/` 与 `scripts/` 每次全覆盖（含 `deploy.sh` 本身）；`docs/` 合并拷贝。

## 三、配置与密钥

| 位置 | 内容 | 谁写 |
|---|---|---|
| `/etc/default/camera-detection` | `JAVA_OPTS`、`JAVA_HOME`、`INSTALL_DIR`、`WORK_DIR`、`APP_HOME`、`CONFIG_FILE`、`MYSQL_PASSWORD`、`ADMIN_USER/PASSWORD`、`JWT_SECRET` | `install.sh` 首次写；`deploy.sh` p7 纠正 JAVA_HOME/JAVA_OPTS |
| `/opt/camera-detection-system/config/application.yml` | 端口、数据源、图片目录、日志文件、归档 cron 等 | `install.sh` 安装时拷贝 |
| `/etc/mysql/mysql.conf.d/zz-camera-detection.cnf` | `innodb_buffer_pool_size`、`max_connections`、`bind-address=127.0.0.1` | `deploy.sh` p4 |
| `/etc/systemd/journald.conf.d/10-camera-detection.conf` | journal 限额：`SystemMaxUse=200M`、`RuntimeMaxUse=50M`、`MaxRetentionSec=30day` | `install.sh` |

- 口令/密钥**只写 `/etc/default/camera-detection`（640 root:root）**，systemd 通过 `EnvironmentFile` 注入，
  `application.yml` 用 `${MYSQL_PASSWORD}` / `${JWT_SECRET}` 引用。
- 这两个占位符**绝不能带空默认值**：带默认值时服务"active 但业务全错"；不带默认值时启动即失败并报
  `Could not resolve placeholder` —— 后者才是可排查的形态。
- 桌面版机器若设了 `http_proxy`，`curl 127.0.0.1` 也会走代理导致验收全红，`verify.sh` 已强制 `NO_PROXY='*'`。

## 四、运行时目录 `/var/lib/camera-detection-system`

| 路径 | 说明 |
|---|---|
| `logs/camera-detection-system.log` | 业务日志（`logging.file.name`），logback 写；按天轮转 30 份压缩 |
| `data/uploads/images/` | `app.upload.image-dir`，旧相机图片通道使用 |
| `data/uploads/defect-images/` | 仅当 `/data` 未挂载时，缺陷图片的回落目录 |
| `.deploy-state` | `deploy.sh` 每次阶段成功后写入「时间 + 阶段」，用于提示续跑起点 |

`run.sh` 启动时只创建 `logs/` 与 `data/uploads/images/` 两个目录 ——
早期版本还会建 `data/uploads/defect-images`，那是迁移前的遗留路径，已移除（应用根本不看它）。

## 五、业务数据 `/data/camera-detection`

图片落盘规则（由 `application.yml` 的 `defect-image.upload.dir` 决定）：

```
/data/camera-detection/images/defect-images/{yyyyMMdd}/{cameraId}/{HHmmssSSS}_{uuid8}.{ext}
例：/data/camera-detection/images/defect-images/20261110/DA8119489/142530123_a1b2c3d4.jpg
```

| 路径 | 谁写 | 谁删 | 保留 |
|---|---|---|---|
| `images/defect-images/{yyyyMMdd}/` | 应用上传（cdsys） | `cleanup-defect-images.sh`（每日 03:30） | 730 天整目录删 |
| `images/defect-images/{yyyyMMdd}/{cameraId}/` | 同上 | `cleanup-zk54-incremental.sh`（每小时 :15，仅 TEST 相机） | 按相机类型 |
| `images/.cleanup-trash/` | 清理脚本 | 同脚本下一轮 | 中转，随即清空 |
| `backup/db/` | `backup-database.sh` | 自身滚动 | 见 §六 |

**删除顺序：先删库再删磁盘**；目录删除一律「先 `mv` 到 `.cleanup-trash` 再 `rm -rf`」，
避免删正在写入的目录导致 `ENOTEMPTY` 而整轮中止。

## 六、备份

| 产物 | 路径 | 频率 | 保留 | 谁写 |
|---|---|---|---|---|
| 全量转储 | `/data/camera-detection/backup/db/full/*.sql.zst` + `.sha256` | 每日 01:00 | 14 份 | `backup-database.sh`（systemd timer） |
| binlog 增量副本 | `/data/camera-detection/backup/db/binlog/` | 每日 01:00（只增量） | 14 天 | 同上 |
| 备份日志 | `/data/camera-detection/backup/db/logs/backup.log` | 每次备份 | 周轮转 8 份 | 同上 |
| 图片副本 | `/var/backups/camera-detection/images/` | 每日 01:00 | 30 天，上限 20GB | 同上（**排除 TEST 相机**） |
| 跨盘数据库副本 | `/var/backups/camera-detection/db/{full,binlog}` | 每日 01:00 | 同源 | 同上 |

- `/data` 与 `/var/backups` 必须在**不同物理盘** —— 副本同盘等于没有副本。
- MySQL 侧 binlog 本体在 `/var/lib/mysql/binlog.0000NN`（`log_bin=ON`、`binlog_format=ROW`、
  `binlog_expire_logs_seconds` 30 天），是 RPO 小于 24 小时的前提，**不可手动删**。
- 图片副本按 `camera_type='TEST'`（`dim_camera` ∪ `camera_status`）排除，防止压测目录把副本撑爆。

## 七、日志

| 日志 | 路径 | 轮转 | 归属 |
|---|---|---|---|
| 业务日志 | `/var/lib/camera-detection-system/logs/camera-detection-system.log` | 天，30 份，压缩 | cdsys |
| 服务日志 | journal（`journalctl -u camera-detection`） | 200M / 30 天 | systemd |
| 部署日志 | `/var/log/camera-detection-deploy.log` | 周，8 份 | root |
| 图片按天清理 | `/var/log/camera-detection-cleanup.log` | 周，8 份 | root |
| 磁盘巡检 | `/var/log/camera-detection-disk-alert.log` | 周，8 份 | root |
| 相机增量清理 | `/data/camera-detection/backup/cleanup_zk54.log` | 周，8 份 | root |
| 备份 | `/data/camera-detection/backup/db/logs/backup.log` | 周，8 份 | cdsys |

轮转规则集中在 `/etc/logrotate.d/camera-detection`。
**logrotate 管不到 journal** —— journal 的限额由 §三 的 drop-in 控制。

## 八、计划任务

| 任务 | 位置 | 调度 | 作用 |
|---|---|---|---|
| 图片按天清理 | `/etc/cron.d/cleanup-defect-images` | `30 3 * * *` | 按 `yyyyMMdd` 整目录删，730 天 |
| TEST 相机清理 | `/etc/cron.d/cleanup-test-camera-images` | `15 * * * *` | 只清 `camera_type='TEST'`，REAL 不动 |
| 磁盘巡检 | `/etc/cron.d/check-disk-usage` | `*/30 * * * *` | 水位告警，同行更新 + 恢复自动关闭 |
| 数据库备份 | `camera-detection-backup.timer` | 每日 `01:00` | 全量 + binlog + 图片副本 |
| 数据清理（应用内） | `DataCleanupTask` | `0 0 2 * * ?` | `camera_images` 等 30 天 |
| 图片归档（应用内） | `DefectImageArchiveTask` | `0 30 2 * * ?` | 主表 31 天 → `*_hist_YYYYMM` |

cron 文件里**不写明文口令**，脚本自行读 `/etc/default/camera-detection`；均用 `flock -n` 防并发。

## 九、数据库

| 项 | 值 |
|---|---|
| 库名 | `wms-new`（含连字符，SQL 里引用必须加反引号） |
| 连接 | `jdbc:mysql://127.0.0.1:3306/wms-new`，账号 `root`，口令来自 `/etc/default` |
| 数据目录 | `/var/lib/mysql`（MySQL 默认，本机 SSD） |
| 表数量 | 全新库 **34 张**；老现场机 41 张（历史累积差异，不是缺表） |
| 月表 | `*_hist_YYYYMM`，由归档任务每日按需创建，保留 730 天 |
| 关键表 | `dim_camera`（相机主档，`camera_type` 决定是否参与清理）、`defect_image_file`（图片事实）、`cfg_camera_defect_mapping`、`sys_user` |

## 十、账号与权限

| 项 | 值 |
|---|---|
| 服务账号 | `cdsys:cdsys`（systemd `User=cdsys`），`/opt` 与 `/var/lib` 归它所有 |
| 600/640 文件 | `/etc/default/camera-detection`（640 root:root）、`config/application.yml`（640 cdsys） |
| 目录属主矩阵 | `/data` 755 root → 各子目录由 install.sh 用 root 建树后 chown 给 cdsys |
| systemd 写权限 | `ReadWritePaths=/var/lib/camera-detection-system`（**新增可写路径必须同步加这里**） |

## 十一、改路径时的联动清单

改任意一个路径，下面 5 处必须同改，否则是"能用一半"的静默故障：

1. **systemd unit** `ReadWritePaths`（新目录不在白名单 → 权限拒绝，日志只说 Permission denied）
2. **`install.sh` 的建目录 + chown/chmod 段**（目录不存在时应用起不来）
3. **`/etc/logrotate.d/camera-detection`**（日志换位置后不再轮转，缓慢吃掉磁盘）
4. **`/etc/cron.d/*` 与环境变量**（清理脚本的 `DIR=`、备份脚本的 `BACKUP_DIR=`）
5. **`verify.sh` 的路径校验项**（验收会发现，但别等到验收才发现）

## 十二、快速定位

| 我要找… | 直接看 |
|---|---|
| 一张缺陷图片 | `/data/camera-detection/images/defect-images/<日期>/<camera_code>/` |
| 某天的清理记录 | `/var/log/camera-detection-cleanup.log`、`/data/camera-detection/backup/cleanup_zk54.log` |
| 应用为什么起不来 | `journalctl -u camera-detection -n 100 --no-pager` |
| 业务报错栈 | `/var/lib/camera-detection-system/logs/camera-detection-system.log` |
| 部署卡在哪一步 | `/var/log/camera-detection-deploy.log` + `cat /var/lib/camera-detection-system/.deploy-state` |
| 最近的数据库备份 | `ls -lh /data/camera-detection/backup/db/full/ \| tail` |
| 实际生效的配置 | 先 `/opt/camera-detection-system/config/application.yml`，没有再 `unzip -p app.jar BOOT-INF/classes/application.yml` |
| 口令在哪 | `/etc/default/camera-detection`（**明文**，640 root:root，禁止外传） |
| 部署包解压目录 | 上传位置（如 `/home/<用户>/deploy`），部署完成后可整体删除 |
