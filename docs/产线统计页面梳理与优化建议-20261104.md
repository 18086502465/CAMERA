### 1.2 各模块职责与相互关系

| 模块 | 职责 | 数据来源 | 依赖关系 |
|---|---|---|---|
| **① hero-card** | 看板模板的 CRUD 入口 + 大屏入口 | `cfg_analytics_dashboard` | 依赖 ⑥ 的模板列表 |
| **② filter-card** | 全局筛选条件 | `inject('filterParams')` 取顶栏工厂/产线/工位 + 本地产品/班次/相机/缺陷/严重度 | 筛选变化 → 触发 `loadData()` |
| **③ kpi-grid** | 6 项核心指标概览 | `/api/v1/analytics/line/summary` 的 `kpi` 字段 | 与 ⑥ 图表共用同一份 `summary` |
| **④ source-hint** | 说明当前走的是「缺陷图片事实表」还是「质量聚合表」 | `summary.dataSourceMessage` | 现场走缺陷图片通道时显示 |
| **⑤ 日聚合卡** | 触发/监控日聚合任务 | `analytics_aggregation_job` / `_schedule` | 与 ② 筛选的时间范围联动 |
| **⑥ 构建器三栏** | 图表的可视化编排 | `cfg_analytics_widget` | 核心产出物 |

**关键数据流**：

```
顶栏工厂/产线/工位筛选 (inject filterParams)
        ↓
② 全局筛选条（补充产品/班次/相机/缺陷/严重度）
        ↓
loadData() → GET /api/v1/analytics/line/summary
        ↓
    summary（响应式对象）
        ├──→ ③ kpi-grid 直接读
        ├──→ ⑥ 中 followGlobalFilter=1 的图表直接读
        └──→ ⑥ 中 followGlobalFilter=0 的图表走 loadWidgetData() 单独请求
                ↓
            widgetData[widgetId]（按图表隔离的数据）
```

**图表渲染链路**：

```
widgets[] (来自 cfg_analytics_widget)
   ↓ widgetMetric(w) 解析 metricJson.metric
   ↓ isChartWidget(w) 判断是否为图表型
   ↓ chartOption(w) 按 metric 分派到不同 option 工厂
   ↓ echarts.setOption
```

### 1.3 图表指标体系（9 种 metric）

| metric | 图表形态 | 数据字段 | 备注 |
|---|---|---|---|
| `plantOverview` | 厂级概览网格 | `plantOverview` | 7 项：检测总量/缺陷总数/高危/首要缺陷/受影响工位/涉及相机/良率 |
| `quality` | 4 格指标 | `kpi` | 检测总数/OK/NG/良率 |

| `defectTrend` | 柱+线组合 | `defectTrend` | 缺陷数 + 异常数 |
| `defectRanking` | 横向条形 | `defectRanking` | Top 12 缺陷 |
| `defectPareto` | 帕累托 | `defectPareto` | 缺陷类型 + 累计占比 |

### 1.4 看板模板管理

| 能力 | 实现方式 | 交互细节 |

## 三、实测发现的生产数据问题（本次一并修复）

梳理页面时用真实浏览器打开产线统计页，发现两个**比样式更严重**的问题：

### 3.1 默认看板混入测试图表

**现象**：画布渲染 7 张卡，其中「缺陷类型帕累托」出现了 3 次（1 正式 + 2 测试）。

**根因**：上一轮排查删除按钮功能时创建的测试图表没清理干净：

| widget_id | 名称 | metric | 所属看板 |
|---|---|---|---|
| 17 | 按钮验证图表-改 | `defectPareto` | dashboard 1（二期工厂） |

## 附：本次同批完成的样式优化（配置页摘要区）

### 根因

`ConfigView.vue` 的摘要区模板使用 `.delivery-summary` / `.summary-card` 两个类名，
但组件自身的 `<style>` 段中**从未定义**它们（在样式表中的匹配数为 0）。
样式缺失 → 元素退化为浏览器默认的行内流布局 → 表现为截图里的**裸文本逐行堆叠**：
标签与数字挤在一起、无卡片、无间距、数字与文字同字号同色。

同目录的 `OperationLog.vue` 恰好定义了 `.summary-card`（因为它是另一个组件，样式不共享），
所以此前一直没人发现这个缺口。

### 修复内容

| 维度 | 修复前 | 修复后 |
|---|---|---|
| 布局 | 无样式，行内流逐行堆叠 | 卡片网格，两组各自横向成排 |
| 结构 | 7 张卡片平铺，语义混同 | 拆为「配置规模」（4 张）与「完整性检查」（3 张），虚线分隔 + 组标题 |
| 圆角 | 无 | 卡片 12px，容器 16px |
| 阴影 | 无 | 卡片 `0 1px 3px rgba(15,23,42,.05)`，容器 `0 1px 4px` |
| 字号 | 标签数字同字号 | 标签 12px / 数值 22px w800，`tabular-nums` 等宽数字 |
| 颜色语义 | 全部默认黑 | 规模卡蓝色系；告警卡橙/红；**值为 0 时降级为中性绿**（现场常态是 0，不该长期显示告警色） |
| 交互 | 无 | hover 上浮 + 阴影加深 + 边框变色 |
| 响应式 | 无 | ≤900px 两组纵向堆叠；≤560px 卡片 2 列 |
| 一致性 | — | 圆角/边框/阴影/字号与相邻 `OperationLog.vue` 的 `.summary-card` 保持同一套语言 |

### 踩坑记录

`.summary-cards` 最初用 `grid-template-columns: repeat(auto-fit, minmax(84px,1fr))`，
但 `.summary-group` 是 flex item、宽度按内容收缩，**`auto-fit` 在收缩容器里会塌陷成单列**
（实测卡片竖着排，把整块区域撑得很高）。改用 `grid-auto-flow: column` + `grid-auto-columns: minmax(84px,1fr)`
才稳定横向展开。
